## 1. 文档使用规则

本文件回答四个问题：用户明确要求了什么，原接口约束了什么，当前方案补充了什么，以及哪些事项仍需确定。开发和验收应按这些类别使用信息。

| 标识 | 类别 | 使用方式 |
| --- | --- | --- |
| F | 用户明确需求 | 作为功能范围和验收依据，保留来源 |
| I | 原接口约束 | 对接时遵守；有歧义则记录差异，不能自行猜测 |
| D | 当前设计建议 | 为实现需求提出的方案，可继续调整，不冒充用户原话 |
| Q | 待确定事项 | 记录影响和当前建议，不将全部问题自动视为开工阻塞项 |
| A | 验收项 | 对应 F 或 I，检查可观察的结果 |

用户最新明确要求更新功能范围；既有外部接口的状态码、字段含义等如需调整，应明确补充协议。用户授权自行设计规则，不等于外部接口方已经接受或实现这些规则。

## 4. 原接口约束单列

| 编号 | 已有约束 | 实施边界 |
| --- | --- | --- |
| I01 | 总体采用 RESTful 通信，说明支持 GeoJSON 与 XML；三张推送单据使用 XML | 新统一任务接口的报文格式尚未确定，不能推断为已要求 JSON |

| I05 | doComplete 上报执行结果，整单 status=0 成功、1 失败、2 作废删除 | 1、2 时整单无效；不能把 2 当作进行中 |

现有 XML 接入和 doAsk、doComplete 应保留。增加通用任务入口及 SFTP 传输能力，应通过共享执行能力对接，不因新增入口直接废弃既有调度协议。

## 5. 建议统一的概念

以下属于 D 类概念设计，用于避免把“服务配置”“监听目标”和“正在传输的任务”混为一体。

| 概念 | 建议标识 | 含义与关系 |
| --- | --- | --- |
| 远端连接配置 | endpointId | 一个可配置的 FTP 或 SFTP 连接，包括地址、认证和允许路径；可被多个监听或任务引用 |
| 拉取监听配置 | listenerId | 引用一个 endpoint，配置扫描目录、周期、识别规则和本地目标；一次扫描可以发现多个数据单元，关联任务与各单元的交付明细 |
| 一次传输任务 | taskId | 一次具体推送或拉取，关联连接快照、文件范围、执行状态和结果；触发来源可以是接口或监听 |
| 稳定来源规则 | sourceId | 旧拉取文档中的来源及识别规则标识，不等同于 endpointId；同一连接可对应多个来源规则 |
| 一轮拉取交付 | transferId | 某次数据交付及验收的关联编号；普通重发沿用，修复后重新交付使用新编号 |

sourceId 与 listenerId 可以建立稳定映射，是否保留两个对外字段属于接口细化事项，不需要因此引入额外服务。

接口触发的单次拉取和定时监听产生的拉取，复用同一套发现或定位、校验、下载、通知、验收处理能力。单次接口拉取不自动创建永久监听；监听配置只描述长期规则，不表示一次文件传输。

## 7. 统一任务接口建议

### 7.1 调用方式

建议新增 `POST /api/transfers/tasks`，通过方向区分推送与拉取；这一路径属于 D 类建议。HTTP 接口承载任务控制，实际文件由选定连接的 FTP 或 SFTP 通道传输。

| 建议参数 | 作用 |
| --- | --- |
| 外部 taskId | 调用方提供的任务关联编号，按调用方和该编号处理幂等 |
| direction | PUSH 或 PULL |
| endpointId | 引用已配置的远端连接；协议从该配置确定 |
| 产品或文件范围 | 指定本次受控路径和产品清单，按方向解释源与目标 |
| listenerId | 单次拉取可选引用已有监听规则；不能因此创建或启动新的永久监听 |
| 业务关联信息 | 保留产品类型、需求编号等实际需要的字段；精确报文待定 |

当 listenerId 与 endpointId 同时提供时，应验证其关联一致；路径仍必须落在允许范围。接口不应允许通过临时报文绕过连接配置任意指定地址、口令或目录。

接口收到任务后返回接收结果和任务关联信息，异步执行。补充任务状态查询能力便于页面和调用方核对，但查询不自动取代既有回调和验收回执。

### 7.2 与原 XML 接口的关系

原 XML 任务通过适配转换为内部推送任务。由于原文没有 endpointId，可继续通过来源系统和 type 解析路由，再引用已配置连接。新增通用接口可以直接引用 endpointId；两种入口共用校验和传输执行能力。

原 XML 任务继续发送 doAsk、doComplete；统一入口的推送分支也保留预检查反馈与最终结果通知，按调用方绑定的通知协议发送。拉取分支保留拉取结果通知和平台验收回执。通用接口的回调、查询字段和报文格式需要单列协议，不把新增字段直接塞进旧 XML 使原对接方无法解析。

## 8. 配置字段建议

### 8.1 远端服务配置

| 类别 | 建议字段 |
| --- | --- |
| 基本信息 | 名称、endpointId、协议、地址、端口、备注、启用状态 |
| 访问范围 | 允许读取和写入的根目录、连接配置适用范围 |
| FTP 参数 | 用户名、凭据引用、数据连接方式等按实际服务器配置 |
| SFTP 参数 | 用户名、密码或私钥认证方式、凭据引用、主机身份校验配置 |
| 执行参数 | 连接超时、无数据进展超时、并发限制、重试配置 |
| 检查记录 | 最近检查时间、可达结果、读写及校验能力、失败原因 |

SFTP 的密码或私钥形式、主机身份校验属于实现建议及接入条件，不是用户已经指定的具体认证方案。页面不回显口令或私钥原文，日志也不保存这些秘密。

FTP 与 SFTP 应分别实现连接和文件操作适配。不能把 FTP 的数据通道探测、SIZE、重命名命令原样套在 SFTP 上，也不能假定任一协议必然提供远端 SHA-256。当前严格推送设计仍要求远端实际校验或完整回读实际文件。

### 8.2 拉取监听配置

建议包含 listenerId、endpointId、来源规则标识、远端扫描范围、文件或目录包模式、匹配规则、扫描周期、就绪判断、校验等级、本地目标和业务访问映射，以及启用状态、最近与下次扫描时间。

同一 endpoint 可以配置多个目录监听。对于监听之间或接口调用与监听之间的重叠，建议按同一 endpoint、归一化远端路径、可比较的源版本及相同交付范围进行幂等判断，保留触发来源。交付范围包含稳定的落地目标、业务接收方和要求的校验规则；不同范围分别交付，不能错误合并。源版本记录可以共用，已有交付能否复用需要再核对交付范围；并发命中时通过唯一约束和原子领取保证只执行一次。具体重复范围及消费方识别方式列入 Q，利用已有记录实现，不要求新增复杂业务实体。

## 9. 状态与进度口径

| 维度 | 建议展示内容 | 不能混淆的含义 |
| --- | --- | --- |
| 连接配置 | 启用或停用 | 配置启用不代表当前网络可达 |
| 连接健康 | 未检查、可达、不可达及时间、原因 | 一次任务失败不必然表示服务离线 |
| 监听运行 | 启停、扫描中、最近结果、下次扫描时间 | 监听启用不代表此时有文件正在下载 |
| 任务执行 | 待检查、校验中、待执行、传输中、发布中、成功、失败、待核对 | 文件传完之后还可能处于校验或发布阶段 |
| 通知 | 待发送、已确认、待重试、待处理 | 通知失败不改写已确认的传输结果 |
| 拉取验收 | 未开始、待验收、成功、失败 | 下载进度 100% 不代表平台已验收 |

进度至少区分任务阶段、文件数和字节数。原 XML 的 fileCount 是产品包数，不能直接作为物理文件进度分母。

建议字节进度按本次任务的唯一业务内容计算，当前失败文件重试时不累计旧尝试的字节；回读校验流量和协议开销也不重复计入完成比例。已传输、已校验的量可分别展示。总量尚在扫描统计时显示“扫描中／总量待确定”，不编造百分比。

服务停用的建议语义是停止接收该服务的新任务或产生新的监听任务，已在途任务按原快照完成。立即中止、暂停后续传、取消整单属于独立操作需求，当前尚未确认。

## 10. Java 与页面架构约束

F13、F14 已明确：使用 Java，采用非前后端分离方式。建议由同一 Java Web 应用提供服务端页面、表单处理、对外任务 API、回调接收和后台任务执行。

页面可由服务端模板生成；需要更新进度时可使用页面中的轻量请求或定时刷新。对外提供 HTTP API 与服务端页面组织方式可以并存，不要求建立单独部署的前端工程。

Spring Boot＋Spring MVC＋Thymeleaf 是可参考的实现组合，属于 D 类建议。Java 版本、框架版本、数据库、FTP/SFTP 客户端库和页面样式方案仍未选定，不把示例组合写成不可调整的需求事实。

实现参考：[Spring 服务端 Web 页面指南](https://spring.io/guides/gs/serving-web-content/)、[OpenSSH sftp 手册](https://man.openbsd.org/sftp)。这些资料用于说明技术实现方向，不构成用户需求来源。

| --- | --- | --- |
| Q01 | 是否增加 FTPS 等其他协议 | 已明确范围为 FTP/SFTP；其他协议不默认纳入 |
| Q02 | 统一入口精确 URL、XML 或其他报文、任务查询及认证 | 先按第 7 节建议设计适配边界，正式联调前落定 |
| Q03 | 页面具体数量、布局及进度刷新方式 | 先保证配置、服务展示和详情能力，布局可迭代 |
| Q04 | Java、框架版本、数据库及客户端库 | 实施选型时确定，不影响事实需求整理 |
| Q05 | 单文件规模、文件数量、并发量、扫描周期、验收期限 | 参数化设计，按实际规模确定默认值和验收负载 |
| Q06 | 登录方式、用户角色及操作权限 | 明确管理页与外部接口各自的访问控制方案 |
| Q07 | 暂停、取消、停用时是否中止在途任务 | 当前仅建议停用后不产生新任务，额外动作需明确语义 |
| Q08 | 多监听和单次 API 重叠时的重复范围 | 按相同来源内容和相同交付目标拟定策略，不合并独立消费方 |
| Q09 | 源完成信号、接收端标记、哈希权限和 ACK 结构 | 属于外部对接条件，联调验证后启用对应能力 |
| Q10 | sourceId、listenerId、外部 taskId 的最终接口映射 | 保持概念区别，避免一个标识同时承担互相冲突的含义 |

这些事项应按其影响安排确认。涉及对方协议的部分在对接前落定；页面组织和可配置参数可以先按标注的建议实现，不要求用户一次回答全部问题。
