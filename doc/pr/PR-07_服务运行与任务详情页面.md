## 1. 目标

整合已经实现的连接、监听和任务能力，使操作人员能够在同一 Java 应用内配置服务、查看当前运行情况、定位具体失败阶段，并执行有限的安全操作。PR-02/06 已有可用配置页，本 PR 不推倒重做。

## 2. 页面范围

| 页面/区域 | 必须展示 |
|---|---|
| 配置 | 连接、源/路由、监听及必要通知绑定；受控目录、规则版本和配置校验 |
| 当前服务 `/services` | 名称、协议、启用状态、最近连通观测及时间、检测原因、关联监听和任务 |
| 监听运行 | 启停与运行状态分别显示，最近/下次扫描、范围、发现/复用统计、失败原因 |
| 任务列表 `/tasks` | 外部/内部任务号、方向、协议、来源、阶段、开始时间、文件/字节摘要、通知/验收状态 |
| 任务详情 `/tasks/{taskRecordId}` | 快照、产品/单元、transferId、逐文件进度、技术验证、发布状态、错误、通知和验收时间线 |

任务列表支持按方向、服务、状态和时间过滤及分页。服务没有任务也要显示；历史任务引用已停用配置仍能查看。详情基于任务快照展示实际执行目标，不能用连接当前配置覆盖历史。

## 3. 状态与进度显示

分别显示配置启用、连接健康、监听运行、任务执行、通知和验收，不压成一个“正常/异常”。最近健康观测显示时间，陈旧结果注明，不把一次错误解释为远端进程停止。

进度至少包含总业务文件数、已传/已验证文件数、总业务字节、当前有效传输/已验证字节、当前文件、重试次数、当前阶段和耗时。已传字节与回读校验流量分开；重试回退当前文件进度，不能累计到超过 100%。

总量未知显示“扫描/预检查中，待确定”，零字节文件防除零。传输达到 100% 时继续显示“目标核验中”“发布中”“待业务验收”等实际阶段；不把进度条当终态。

状态示例必须正确呈现：

| 后台事实 | 页面文案示例 |
|---|---|
| 推送已有效发布，完成单未 ACK | 交付成功，完成通知待送达 |
| 拉取技术通过，未验收 | 下载及技术检查通过，待平台验收 |
| 源就绪条件未满足 | 等待源数据就绪，并显示原因/下次检查 |
| READY 写入结果未知 | 发布结果待核对，不显示明确失败 |
| 有子单元被拒，其他仍处理 | 部分单元失败，其他单元处理中 |

速度只显示真实采样值，没有有效采样显示未知。预计剩余时间首版可不显示，不伪造稳定精确值。文件列表、日志及通知明细分页，避免一次渲染数万行。

## 4. 刷新与页面实现

Thymeleaf 服务端渲染，轻量 JS 调用同应用只读接口刷新，默认 2 秒可配置；页面隐藏时降低/停止轮询，关闭页面停止请求。网络故障显示“状态暂未刷新”，保留最后更新时间，不清空成成功或离线。

所有状态源于任务服务/持久化记录，不能通过定时器自行增加进度。接口返回精确大字节值时避免 JS 数字精度导致溢出，可使用十进制字符串/格式化值。资源本地打包，不加入独立前端部署链。

## 5. 首版操作与边界

允许：连接/监听启停、重新检测、监听执行一次、补发指定未确认通知、触发待核对任务的结果核对。每项操作经过权限、CSRF、当前状态检查及操作记录，双击/并发请求不能产生重复执行。

补发通知沿用固定报文和 notificationId，不重传文件；已确认通知默认不重复发送。触发核对只查询和恢复可证实的状态，不提供任意“强制成功”。同一终态失败内容的重新交付依照 PR-05 受控服务另行处理，不做通用“重跑一切”按钮。

不提供未经约定的任务暂停、取消、源文件删除、批量清理或任意状态编辑。停用连接的确认提示明确“停止新任务，在途任务按原快照继续”，不能误导为停止远端 FTP 服务。

## 6. 错误、权限与审计

错误展示阶段、错误码、可定位的文件/交付、首次/最近时间、有限重试次数及当前处理建议；敏感堆栈只在受控日志，不显示账号口令、私钥和令牌。用户输入和文件名输出转义，拒绝 XSS。

管理操作记录操作者、对象、前后状态、时间与结果即可，不扩展审计平台。任务 API 按调用方隔离，不能只隐藏页面链接却放开查询接口。

## 二、明确每个状态究竟表示什么

配置启停、连接健康、监听运行、任务执行、通知和验收分别显示，不能合成一个“正常/异常”。健康状态带观测时间，旧检测注明过期/陈旧；任务哈希失败不能把连接标为已关闭。

必须正确显示这些组合：

- 推送已发布、完成单未 ACK：交付成功，完成通知待送达。
- 拉取技术通过、未验收：下载及技术检查通过，待平台验收。
- 源尚未满足条件：等待源数据就绪，并显示原因/下次检查。
- READY 结果未知：发布结果待核对，不显示确定失败或成功。
- 部分单元失败、其他还在处理：逐项显示并保留处理中汇总，不把整单直接标成功。

错误信息包含阶段、错误码、具体文件/交付、首次/最近时间、重试次数与可执行的处理提示。敏感堆栈留在受控日志；密码、密钥、令牌不进入页面。

## 三、进度来自真实业务记录

展示总业务文件数、已传/已验证文件数、总业务字节、当前有效已传/已验证字节、当前文件、重试次数、阶段和耗时。

业务字节、回读验证流量和重传流量分开。失败文件重试时按当前有效尝试计算，不累加历史尝试把进度推到 100% 以上。上传/下载 100% 后仍须显示校验、发布或验收阶段。

总量未知显示“扫描/预检查中，待确定”；零字节文件避免除零。大字节值从后端到 JS 的表示不得丢精度，可使用十进制字符串或后端格式化值。速度有真实采样才显示；未实现可靠 ETA 时不显示虚构剩余时间。

文件、日志和通知明细分页，不一次加载数万条记录。页面定时器只能触发查询，不能自行增加百分比。

## 四、实现同应用轻量刷新

服务端渲染首屏，轻量 JS 调用同应用只读接口刷新状态；原实施初值 2 秒，可配置。页面隐藏时降低或停止轮询，关闭页面终止请求。

网络失败保留上次数据、更新时间和“状态暂未刷新”提示，不把查询失败解释成任务成功或服务离线。恢复连接后按服务端事实更新，不能倒退已确认终态。

静态资源本地提供，沿用现有样式；无数据时有明确空状态，尚未实现的操作不显示为可用。

## 五、只开放已有语义的管理操作

允许连接/监听启停、重新检测、监听执行一次、补发指定未确认通知，以及触发待核对任务的结果核对。每项操作都经过权限、CSRF、对象当前状态校验，并记录操作者、对象、前后状态、时间与结果。

双击或并发提交不能创建重复执行；具体实现复用后台原子领取/幂等，不能只禁用前端按钮。

补通知沿用原 notificationId 和固定报文，绝不调用文件传输；已确认通知默认不补发。核对操作只读取并恢复有证据的外部状态，不能提供“强制成功”。

停用连接的确认文案说明“停止接收新任务，在途任务按原快照继续”，不能写成关闭远端 FTP 服务。不增加任意重跑、任务暂停取消、源文件删除、批量清理或状态编辑。

用户输入、文件名和错误内容统一转义；查询接口本身也做权限隔离，不能只隐藏页面入口。

## 六、用真实状态验证页面

基于前序实现生成测试任务和状态，验证下表所有组合，尤其是上传完成但校验中、拉取待验收、通知失败但交付成功、未知发布、多单元部分失败和连接修改后的历史快照。

执行控制器/模板自动化测试，并在浏览器实际查看登录、导航、过滤分页、详情刷新、错误提示和管理操作。浏览器证据需对应本次真实运行；未运行浏览器就标为未验证，不能拿 HTML 文件存在代替验收。

回归相关 API 授权和后端任务测试。交付页面/接口改动、实际截图或其他浏览器验证记录、命令和结果；回退页面不能改动任务终态或删除业务记录。
