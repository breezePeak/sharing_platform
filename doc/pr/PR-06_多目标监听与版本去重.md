## 1. 目标

配置多个 FTP/SFTP 监听目标，独立设置目录和规则、周期与启停；周期扫描发现新版本后，复用 PR-05 拉取链。一个目标失败或有大文件下载不能阻塞其他目标。

## 2. 监听配置与来源继承

监听字段包含 listenerId、名称、endpointId、稳定 sourceId/规则版本、源范围、数据单元与识别规则、就绪规则、校验等级、稳定交付目标和接收方、周期、初次扫描模式、启用状态、最近/下次扫描时间和最近结果。

来源内容直接复用 PR-05 配置，不在监听里另建一份互不一致的来源解析器。编辑名称、周期、超时不换 sourceId，不清空历史。修改源根、单元边界、交付范围时创建配置版本，明确继承或重扫范围并展示影响，不静默把所有旧文件变成新增。

实现配置页新增/编辑/启停、手动执行一次、最近扫描结果和关联任务入口。同一 endpoint 可配置多个监听。停用监听不强制取消已经创建的任务；手动一次不改变长期启用状态。endpoint 停用时不创建任何新监听任务。

## 3. 调度与就绪观察

使用数据库存储扫描计划、运行记录和候选观察，由轻量定时触发器检查到期监听。每轮原子领取，同一监听上一轮未完成时跳过/合并并记录原因，不能累积无限触发。

调度触发、目录扫描与文件传输不能共用一个被大文件占死的线程。设置有界扫描池和传输池、全局及每 endpoint 配额；无额度时持久化排队。加公平调度，不能让高频失败或大目录监听长期占满全部名额。

开发初值：扫描间隔 60 秒、连续 3 次有效一致观察、最小观察时长 120 秒，均为 P 类可配置初值。只有完整成功的扫描能计数，部分目录失败不能当文件已删除。生产方标记/清单优先，稳定观察只是兼容就绪条件，不是生产完整性证明。

使用可注入时钟测试周期和观察窗口，不通过等待几分钟制造测试通过。记录每轮范围、候选/新版本数量、创建或复用任务数量、错误和耗时。

## 4. 初次扫描

默认 IMPORT_EXISTING，处理当前范围尚未交付的数据。明确选择 BASELINE_ONLY 时，首次完整有效扫描只登记历史基线，不创建下载交付；保存初始化选择、时间与范围。初始化失败不能把部分结果标成完整基线，后续继续初始化并可诊断。

基线只影响对应监听/来源的既定交付范围，不能把另一接收方应拿到的数据全局标成已处理。后续新版本照常处理。禁用再启用、重启、修改周期均不能重新偷偷基线化而漏数据。

## 5. 与 API、重叠监听的去重

所有触发进入同一候选/版本/交付服务，记录 triggerType 和所有触发关联。API 引用 listenerId 时校验 endpoint 一致，路径不得扩大授权范围；停用的监听可提供配置给有权限的单次调用，但不恢复定时。

跨监听按公共约定的规范化交付键和数据库唯一约束竞争，不能只按各自 listenerId/sourceId 加锁。若版本算法不可比较或规则不同而不能安全判断是否同一交付，保存配置时提示冲突并要求明确范围策略，不能猜测去重。

同内容同版本同接收范围复用交付；不同接收方/落地目标/校验要求分别交付。等待就绪、失败、通知待补和待验收记录均复用原处理关系；每一轮扫描不能创建一条新失败记录掩盖同一问题。

## 6. 重启与停用

监听配置、初始化状态、候选次数、最小观察起点、版本历史和 nextRunAt 持久化。进程重启后按启用状态恢复调度，先核对中断扫描，不清空去重历史。

错过的周期首版合并为一次补扫，不为每个错过时点补出任务洪峰。停用仅影响后续触发；已受理单次任务、已存在的下载和验收继续按原快照。

## 7. 修改与交付

新增 listener 配置/页面、扫描计划及记录迁移和调度器。复用 PR-05 的来源、就绪、下载、交付与回执，不复制文件处理实现。用两个以上真实协议测试服务/目标证明独立运行与去重。

## 一、把监听配置与来源配置关联起来

保存 listenerId、名称、endpointId、稳定 sourceId/规则版本、源范围、周期、初次扫描模式、启用状态、最近/下次扫描时间和最近运行结果。单元识别、就绪、校验、目标、接收方和访问映射引用已有来源规则，不创建相互冲突的副本。

## 二、实现持久化调度、原子领取和资源隔离

轻量定时触发器只查找已启用且到期的监听。每轮用数据库状态/版本条件原子领取，提交后交给有界扫描池。上轮未完成时合并或跳过本次触发，保存原因，不堆积无限扫描。

扫描池与文件传输池分开，调度线程不直接下载文件。全局和每 endpoint 有并发额度，无额度时保留可查询的排队/下次执行信息。采用公平调度，避免一个大目录或持续失败目标长期占满资源。

每轮保存监听及配置版本、扫描范围、开始结束时间、候选/新版本数量、创建/复用数量、错误和耗时。原子领取、重试和恢复遵守既有执行边界，不引入分布式调度或消息队列。

## 三、复用就绪观察，区分有效扫描与部分失败

沿用来源的清单、标记、发布规则；没有生产方完成信号时才使用兼容稳定观察。原实施初值为扫描间隔 60 秒、连续 3 次有效一致观察、最小观察时长 120 秒，全部可配置，不能写成用户指定值。

稳定判断比较完整文件集合及逐文件大小、时间等既定属性，不只比较目录时间。集合/属性变化重置稳定次数；失败或部分扫描不增加次数，也不能推断未读到文件已删除。

候选次数、观察起点和来源版本持久化，重启后继续。使用可注入时钟测试观察窗口，不让测试实际睡眠几分钟。

稳定观察只能表示达到约定拉取条件，不能对外宣称上游已严格生产完整。版本与 HASH/BASIC 校验等级保持分开。

## 四、明确处理首次扫描

默认 IMPORT_EXISTING：当前范围未交付的数据按正常候选/就绪流程导入。

显式选择 BASELINE_ONLY：首次完整有效扫描仅登记该范围历史基线，不创建下载交付；保存选择、初始化时间、范围和完成状态。初始化中途失败不能把部分扫描标成完成，重启后继续初始化并保持可诊断。

基线只作用于既定来源/交付范围，不把其他接收方应收数据全局标成已处理。后续新版本正常处理；停用再启用、修改周期或重启不重新基线化。

## 五、打通 API、手动一次和周期扫描的同一执行链

API 引用 listenerId 时校验 endpoint 一致、调用权限和路径范围，继承同一稳定 sourceId 和交付规则。手动一次与 API 使用同一业务入口，不改变监听长期启用状态。

所有触发复用 PR-05 的候选、源版本及规范化交付键，记录 triggerType 和任务关联。同版本同交付范围的 API 与多个监听并发命中，用 PostgreSQL 唯一约束和原子领取选中一轮交付；不能只按 listenerId/sourceId 分别加锁。

不同接收方、落地目标或校验要求分别交付。版本依据不可比较而范围重叠时，配置页明确提示并按原策略阻止未明确的冲突配置，不猜测相同、不悄悄重复交付。

已在等待就绪、等待重试、待通知或待验收的对象延续原处理关系，不能每轮扫描生成新的失败交付掩盖旧问题。

## 六、实现停用与重启恢复语义

停用监听只关闭后续周期触发；已经创建的任务和交付继续。有权限的用户可使用停用监听配置手动执行一次，但不恢复周期。停用 endpoint 则拒绝新的 API/监听任务，原任务仍按快照继续。

重启时恢复配置、初始化状态、候选、版本历史和到期计划；先核对上次中断扫描，不清空去重记录。错过多个周期合并为一次补扫，不为所有错过时点补任务洪峰。
