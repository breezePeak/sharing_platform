# PR-04｜FTP/SFTP 推送、严格校验、整单发布与回调

| 项目 | 内容 |
|---|---|
| 建议标题 | `feat: deliver verified push transfers with atomic-ready publication` |
| 建议分支 | `codex/pr-04-push` |
| 前置 | PR-01—PR-03 |
| 需求映射 | F01—F03、F07、F16；I02—I08；A01、A03、A04、A08、A14 |
| 状态 | 待实施；所有测试未执行 |

标题中的发布语义由有效完成标记与接收方消费规则共同构成，不是 FTP/SFTP 提供跨文件数据库事务。

## 1. 目标

通过统一入口提交产品目录，真实推送到 FTP 和 SFTP，完成全部预检查、固定清单、目标内容验证、整单发布和结果反馈。原 XML 经适配进入同一执行链；外部契约未确认时只在标注的测试对接配置运行。

## 2. 推送路由与输入边界

原 XML 按认证调用方/type 唯一解析推送路由；新增入口引用 endpointId，并且只能选择授权 sourceRoot 和 targetRoot 范围。为路由提供最小配置入口，字段含调用方、type、源根、endpoint、目标根、通知配置和版本；不另建管理系统。

product 统一为产品目录，内部保留相对结构；单独文件需要置于产品目录。fileCount 始终为产品包数，物理文件数单列。任务下发代表生产方确认固定版本就绪，系统检查不能替代生产方承诺。

## 3. 预检查实现

按 [推送流程第 4 节](../01_推送流程.md) 建立检查器及证据记录，不只做 exists。检查覆盖：

| 组 | 必须执行的检查 |
|---|---|
| 接入和持久化 | 鉴权、安全解析、任务幂等、持久化后受理 |
| 请求和路由 | 必填项、产品数/ID、唯一且启用的路由、调用权限 |
| 路径和集合 | 源目录真实路径、重复/包含范围、符号链接/特殊文件、目录和目标映射冲突 |
| 源可读与固定 | 实际逐文件读取；配置的临时名/零字节规则；流式大小和 SHA-256；读取前后属性及整目录复查 |
| 清单 | 产品全集、目录结构、物理文件路径/大小/hash、清单版本与固定摘要持久化 |
| 目标条件 | 两种协议实际操作能力、严格验证路径、独占目标目录冲突、已知容量情况 |

清单冻结失败不进入可执行状态。没有上游预期清单时仅保证观察到的固定集合，不能声称检查出未知漏生成文件。

预检结果与待发反馈同事务保存。成功反馈取得约定 ACK 前保持 WAITING_FEEDBACK，不发送业务文件；探测文件不是业务交付。拒绝反馈使用 doAsk result=1/rejectrason 或新 JSON 同义契约，默认不再发 doComplete。

## 4. 文件传输与严格验证

执行前再次确认固定源及状态，领取唯一执行资格。使用任务快照与协议适配器，在本任务独占区域写临时文件；临时命名不能撞上合法业务文件。

每个文件必须满足：

```text
预检清单大小 = 上传实际读取字节数 = 目标实际字节数
预检清单SHA-256 = 上传读取摘要 = 目标实际内容摘要
```

目标没有远端哈希时通过 FTP/SFTP 完整回读目标文件计算摘要；不可只回读自己上传的 `.sha256` 文本。不支持远端哈希且不能回读的服务拒绝严格推送。大文件流式读取，不整体放入内存。

目标通过验证后发布单文件正式名，核对改名结果并记录已验证。网络中断按单文件有限重试，未完成文件首版从头传；已验证文件只能在重新核对固定基准后复用。源变化立即终止旧任务，不重新生成清单继续放行。

## 5. 整单发布与未知结果

全部文件结束后复核源和目标集合、目录、原产品全集、逐文件核验记录及临时残留。任一必需项缺失，不发布 `_READY`。

固定生成 `_manifest.xml` 字节与摘要，先上传并核验清单，再发布绑定 taskId、清单摘要和产品数的 `_READY`。标记本身先写临时名，最后发布并读回核对。接收方只消费有效标记及匹配清单；该规则要在外部联调确认。

标记写入/改名响应丢失时进入 RECONCILING，读取实际标记和清单定位结果。没有核清前不得发送失败完成单、重建原目标或发布相反结果。记录发布前意图使 PR-08 能测试所有崩溃窗口；本 PR 已须有正常核对路径，不能把关键保护延后。

## 6. 完成反馈与状态

确认成功后保存执行成功及固定完成通知，原 XML status=0。确认执行失败且未有效发布时 status=1；status=2 保留作废删除语义，本 PR 不实现未约定的删除操作。

完成单保留原 product 全集与原 fileCount，失败和未执行产品也在其中。目标 productPath 按约定返回相对 targetRoot 的交付位置；失败路径仅供诊断。通知失败只补通知，执行成功不回退失败。

记录上传、目标验证、发布、等待通知各阶段及实际进度。上传字节 100% 不等于整单成功；回读流量单列。源路径、目标路径和错误只向授权管理者/调用方展示。

## 7. 修改与交付

实现 push 业务、固定清单与文件明细迁移、路由最小配置、清单/标记序列化、双协议测试及回调样例。使用 PR-03 的任务/通知/状态机制和 PR-02 协议适配器，不复制第二套。

## 8. 验收与测试

| 编号 | 场景 | 预期 |
|---|---|---|
| 04-T01 | FTP 与 SFTP 各推送多产品、多层目录 | 全部内容/hash/目录一致，清单与标记有效，完成反馈可确认 |
| 04-T02 | fileCount 不符、空产品、路由不唯一 | 预检拒绝且原因明确，不传业务文件 |
| 04-T03 | 越界、链接、重叠产品、大小写/临时名冲突 | 拒绝或使用已约定无冲突映射，无越权文件 |
| 04-T04 | 预检后修改源文件但维持相同长度 | 上传读入摘要不符；不得改清单放行 |
| 04-T05 | 远端文件同大小但内容损坏 | 目标核验失败，无有效 READY |
| 04-T06 | 无远端 hash、有回读；两者皆无 | 前者真实回读成功；后者预检拒绝 |
| 04-T07 | doAsk ACK 丢失 | 同反馈补发，确认前不传业务文件 |
| 04-T08 | 中途断网后恢复 | 受限重试原文件/原任务，无超 100% 进度 |
| 04-T09 | 多产品之一最终失败 | 整单无有效 READY；完成单保留全部产品 |
| 04-T10 | READY 发布成功但响应丢失 | 核对后恢复成功，只发一致结果，不重传/覆盖 |
| 04-T11 | 完成通知 ACK 丢失 | 只补固定完成单，远端数据无新增写入 |
| 04-T12 | 源集合变化、目标混入额外业务文件 | 发布前复核阻止整单成功 |
| 04-T13 | 执行中修改/停用连接 | 原任务使用原快照；新任务按新配置/停用规则处理 |
| 04-T14 | 预检查拒绝 | 只有拒绝反馈，不默认再发执行完成单 |

必须保留真实双协议验证记录。旧 XML 暂定样例通过与外部真实联调通过分别报告。

## 9. 回退

关闭 PUSH 新任务入口，停止创建新任务，保留在途状态与通知。已经发布的数据不能通过回退脚本删除；发布未知的任务保留待核对。迁移增量兼容，旧版本不能识别新状态时不得盲目降级运行执行器。

## 10. 可直接执行的开发提示词

```text
执行 PR-04，按 V1.1 推送流程和本任务书打通完整推送链，复用既有核心、协议和通知组件。
同时支持 FTP/SFTP，原 XML 与新 JSON 共用推送服务；旧对接契约未确认处明确标识。
实现全部预检查、固定文件清单、上传源摘要核对、目标实际大小及 SHA-256 验证。
没有远端哈希时全量回读真实文件，不能降级或只验证清单文本。
成功预检反馈 ACK 前不上传业务数据；全部验证后才最后发布绑定清单的 READY。
发布结果不明先核对；失败完成单保留所有原产品；回调失败只补通知。
按 04-T01—04-T14 用真实 FTP/SFTP 和本地测试接收端验证，特别覆盖同大小损坏和丢失响应。
不要加入暂停取消、自动删除、分片续传或其他协议。报告真实测试和外部未验证项，不自动合并。
```
