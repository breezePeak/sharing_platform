## 2. 首版实施默认值（P 类）

| 决策 | 本轮采用的开发默认方案 | 边界 |
|---|---|---|
| P01 架构 | 用户指定 JDK 11；单个 Spring Boot Web 应用；MVC + Thymeleaf | 页面、API、执行器一个部署单元；不创建独立前端工程 |
| P02 版本 | 已落地 Spring Boot 2.7.18 | 兼容 JDK 11 的实施选择；维护风险见实施决策 |
| P03 持久化 | 用户指定 Spring Data JPA；Flyway 管理结构；各环境直接连接 PostgreSQL | 测试默认使用隔离库与随机 schema；用户本轮授权本机同库的随机测试 schema，不引入 H2/MySQL 替代 |
| P04 文件协议 | FTP 用 Apache Commons Net；SFTP 用 Apache MINA SSHD 的 SFTP 客户端 | PR-02 锁定实际可解析的正式依赖版本；不假定 SFTP 具备远端命令执行权限 |
| P05 执行 | 单实例、数据库持久化任务与通知、有界线程池、原子领取 | 不引入 Redis、Kafka、分布式调度、微服务或通用工作流引擎 |
| P06 新接口 | 新统一入口采用 JSON，保留原 XML 接入/反馈/完成适配 | JSON 是本轮实施选择；旧 XML 的未定根节点、大小写、ACK 不擅自认定 |
| P07 页面与接口边界 | 用户指定页面无需登录，不引入 Spring Security；PR2 表单使用会话 CSRF | 后续外部 API 按独立调用方鉴权；部署时限制管理页面网络可达范围 |
| P08 页面刷新 | 同应用页面内定时读取状态，默认 2 秒，可配置 | 不要求 WebSocket；总量未知不显示虚构百分比 |

旧稿的 Java 21 / Boot 4 / Spring JDBC / 管理员登录建议已被用户后续要求覆盖，不能用于重做 PR1/PR2 或后续阶段。实际版本与核对依据见 [实施决策](../implementation-decisions.md)。

## 4. 每个 PR 的交付要求

每个 PR 均提交实际实现、当前范围的自动化测试、配置示例和文档变更。完成报告包括修改文件、执行命令、实际测试数量与结果、未验证项、外部依赖；测试不能全部推迟到 PR-08。复用前序模块，不在每个 PR 中重新实现 FTP/SFTP 客户端、状态机和通知机制。

分支建议为 `codex/pr-01-foundation` 等任务书指定名称，合并目标为仓库当时的主开发分支。一个 PR 完成并检查通过后再进入下一个；不得自动合并，不创建空 PR。存在未提交用户修改时保留，不覆盖。

**不以“类已经创建”“页面有按钮”“HTTP 返回 200”“文件字节到 100%”代替业务验收。**

## 5. 首版不做的内容

不新增 FTPS、对象存储、文件内容转换、自动解压、源文件自动删除、分布式集群、复杂权限、任意任务暂停/取消、分片断点续传。中断文件首版可整文件重传；已验证成果只能在固定基准核对后复用。必要安全校验、持久化、去重、通知补发及恢复属于本版范围，不因此删减。

## 6. 联调待定项的推进方式

| 外部事项 | 不阻塞的开发工作 | 正式接入门槛 |
|---|---|---|
| 旧 XML 实际样例及 `ProductList/productList` | 实现独立适配层、已知字段规则及明确标注的测试样例 | 用真实样例建立契约测试；输出唯一产品列表，未确认的旧对接配置不得启用生产 |
| doAsk/doComplete ACK | 实现持久化通知、固定报文、有限重试及测试接收端 | 持久化接收语义、关联字段和重复响应得到确认 |
| 接收方 `_READY` 消费规则 | 实现标记最后发布，真实测试文件服务验证 | 接收方遵守未就绪不消费的规则；单方实现不算外部验收通过 |
| 源冻结、源清单与 HASH 基准 | 实现配置化判断、BASIC/HASH 分离 | 按实际来源确定保证范围，严格模式不得降级 |
| 拉取交接路径和业务验收 | 实现通知/回执与测试接收端 | 业务平台实际可访问 dataLocation 并回传有效验收结果 |

未定项记录在配置和联调清单中。开发不需要等待全部外部条件齐备；生产验收不能把测试接收端的结果当作对方系统已经支持。
