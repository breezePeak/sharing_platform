## 1. 目标

在已有 `sharing_platform/` 工程完成可运行、可测试、可持久化、可打开页面的最小基础。此 PR 不实现文件推送和拉取，也不提前生成大量未使用的业务类。

## 2. 实现范围

### 2.1 先对齐现有内容

读取四份基线和 [公共约定](01_公共实现约定.md)，比对远端最新代码。将仓库较旧的流程文档与本包最新基线对齐（事实依据、边界为 V1.2；推送、拉取为 V1.1），保留 F/I/D/Q 分类及后续用户变更。记录 SFTP、多监听、统一入口和状态页面增量，避免整份替换时丢失后来编辑。

保留 `com.siwei.App` 与现有目录。清理示例 Hello world 注释及 JUnit 3 测试，迁移到选定 Boot 测试 starter 管理的 JUnit Jupiter，不硬编码一个未经核对的 JUnit 主版本。

### 2.2 构建与依赖

使用用户指定的 JDK 11 和兼容的 Spring Boot 2.7.18，通过依赖解析、启动和 MVC 测试实测。依赖包括 MVC、Thymeleaf、校验、`spring-boot-starter-data-jpa`、Flyway、健康检查和测试；不引入 `spring-boot-starter-security`、`spring-security-test` 或独立 JDBC starter，不编写 JdbcTemplate 仓储。使用 PostgreSQL 驱动；Boot 管理的 Flyway 8.5.13 内置 PostgreSQL 支持，无需新版独立模块。具体版本和维护状态记录于实施决策。

增加 Maven Wrapper 的 Unix/Windows 启动脚本，固定 Maven 正式版本；配置可执行 JAR。无前端独立构建步骤，无 Node/npm 要求。建立 GitHub Actions 测试构建，不在 CI 中使用客户凭据或要求访问客户 FTP。

### 2.3 配置、数据与页面基础

提供 `local`、`test`、`prod` 配置分层，所有运行环境及数据库集成测试统一使用 PostgreSQL，不引入 H2 或 MySQL 兼容方案。local 可连接本机/专用实例；test/CI 使用独立测试实例或测试库，必须与开发和生产数据隔离；prod 外置连接参数。纯单元测试不要求数据库。缺少必需配置、连接失败或迁移失败时明确报错，不能静默回退其他数据库。

用户没有指定 PostgreSQL 主版本；按本机实际部署固定 PostgreSQL 13.23，验证 JPA/Hibernate、驱动和 Flyway 兼容，测试与目标部署使用相同主版本。开发、测试和 CI 直接连接原生 PostgreSQL，不使用 Docker。版本选择不扩展为多版本支持项目。

实现最小 Flyway 迁移、JPA 实体与 `JpaRepository` 真实读写测试，仅建立必要的系统元数据表。使用 `spring.jpa.hibernate.ddl-auto=validate`、`spring.jpa.open-in-view=false`，表结构由 Flyway 管理，不让 Hibernate 自动建表或更新表。验证空库初始化、重复启动、已有 V1 兼容和基础升级。CI 必须执行真实 PostgreSQL 集成测试，不用 Mock/其他数据库替代；连接和防误连规则遵守公共约定第 3.1 节。

提供 `/services`、`/config`、`/tasks` 的直接访问导航与诚实空状态，无登录页、管理员账户或管理员必需参数。未开发功能标注未配置/暂无记录，不放演示数据。静态资源本地提供，不依赖 CDN。最小健康接口不公开配置、环境变量、凭据或完整堆栈。

本 PR 仅提供只读基础页面，不建立安全过滤链或通用认证框架，不开放配置写入表单和业务 API。`POST /config` 返回 405，未实现的 `/api/**` 返回 404，不伪造受理。请求防伪与调用方校验随对应 PR 的真实写入/API 能力实施，不依赖 Spring Security。统一错误页、参数错误、日志脱敏和关联 traceId。

### 2.4 文档

补全根 README：工程子目录、JDK、PostgreSQL 准备、独立测试库、配置、测试、打包、启动、访问、停止与数据目录。先说明数据库条件，再列启动命令。实施决策区分用户指定的 PostgreSQL/JDK 11/JPA/无登录/无 Spring Security/无 Docker，与 Boot/Flyway 等具体版本和测试环境选择，并注明核对来源。
