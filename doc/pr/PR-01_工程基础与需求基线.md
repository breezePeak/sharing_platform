## 1. 目标

在已有 `sharing_platform/` 工程完成可运行、可测试、可持久化、可打开页面的最小基础。此 PR 不实现文件推送和拉取，也不提前生成大量未使用的业务类。

## 2. 实现范围

### 2.1 先对齐现有内容

读取四份基线和 [公共约定](01_公共实现约定.md)，比对远端最新代码。将仓库较旧的流程文档与本包最新基线对齐（事实依据、边界为 V1.2；推送、拉取为 V1.1），保留 F/I/D/Q 分类及后续用户变更。记录 SFTP、多监听、统一入口和状态页面增量，避免整份替换时丢失后来编辑。

保留 `com.siwei.App` 与现有目录。清理示例 Hello world 注释及 JUnit 3 测试，迁移到选定 Boot 测试 starter 管理的 JUnit Jupiter，不硬编码一个未经核对的 JUnit 主版本。

### 2.2 构建与依赖

原稿以 Java 21、Spring Boot 4.1.2 为未实施起点的默认建议。本轮先沿用仓库已落地并可验证的版本，不强制降级；确需调整则记录理由，并通过依赖解析、启动、MVC 测试实测。新增所需 MVC、Thymeleaf、校验、JDBC、Flyway、Security、健康检查和测试依赖；数据库使用 `org.postgresql:postgresql`，为所选 Flyway 版本添加匹配的 `org.flywaydb:flyway-database-postgresql`，具体 starter 名称以该 Boot 版本实际发布坐标为准；不要凭旧版本经验填写无法解析的 artifact。

增加 Maven Wrapper 的 Unix/Windows 启动脚本，固定 Maven 正式版本；配置可执行 JAR。无前端独立构建步骤，无 Node/npm 要求。建立 GitHub Actions 测试构建，不在 CI 中使用客户凭据或要求访问客户 FTP。

### 2.3 配置、数据与页面基础

提供 `local`、`test`、`prod` 配置分层，所有运行环境及数据库集成测试统一使用 PostgreSQL，不引入 H2 或 MySQL 兼容方案。local 可连接本机/专用实例；test/CI 使用独立测试实例或测试库，必须与开发和生产数据隔离；prod 外置连接参数。纯单元测试不要求数据库。缺少必需配置、连接失败或迁移失败时明确报错，不能静默回退其他数据库。

用户没有指定 PostgreSQL 主版本；本 PR 根据目标部署条件选择、固定并记录数据库版本，验证 JDBC/Flyway 兼容，测试与目标部署使用相同主版本。版本选择不扩展为多版本支持项目。

接入 PostgreSQL 版 Flyway 最小迁移和真实仓储读写测试；可用必要的系统元数据表验证迁移，不预建所有后续业务表。迁移 SQL 以 PostgreSQL 为目标，验证空库初始化、重复启动和基础升级场景。CI 必须执行数据库集成测试；环境不足单列未验证原因，不用 Mock/其他数据库结果替代。数据源连接信息和测试库防误连规则遵守公共约定第 3.1 节。

提供 `/login`、`/services`、`/config`、`/tasks` 的基础导航与诚实空状态。未开发功能明确标注未配置/暂无记录，不能放演示数据冒充实时状态。静态资源本地提供，不依赖外部 CDN。提供最小健康接口，不公开配置、环境变量、凭据和完整堆栈。

一个管理员账户由外部配置初始化；不提交默认弱密码。管理表单保留 CSRF；预留 API 独立鉴权边界但不伪造业务接口。统一错误页、参数错误信息、日志脱敏和关联 traceId。

### 2.4 文档

补全根 README：工程所在子目录、JDK、PostgreSQL 准备及连接参数、独立测试库、配置、测试、打包、启动、访问页面、停止和数据目录。先说明数据库就绪条件，再列应用启动命令。增加 `doc/implementation-decisions.md`：PostgreSQL 类型记录为用户 F17，其余技术栈、具体版本和环境安排记录为 P 类实施选择并注明核对来源。
