## 数据共享平台｜各 PR 共用实现约定

> 当前用户约束：JDK 11、Spring Data JPA、页面无需登录、不使用 Spring Security、直接连接 PostgreSQL、不使用 Docker。以下正文按此实施；Boot 2.7.18 / Flyway 8.5.13 的具体版本为兼容选择，见 [实施决策](../implementation-decisions.md)。

日期：2026-11-13。PostgreSQL 修订版；数据库类型来自用户新增 F17，以下其余约定为 P 类实施设计；需求事实以 [00_事实需求依据](../00_事实需求依据.md) 为准。每个 PR 都应遵守本页，修改公共约定时给出原因并同步受影响测试。

### 1. 工程与代码组织

在现有 `sharing_platform/` Maven 工程开发，保留 `com.siwei.App`。按能力组织 `config`、`endpoint`、`transfer`、`push`、`pull`、`notification`、`web` 等包即可；不要为目录形式创建无实现的多模块架构。

所有页面和静态资源从同一 Java 应用提供。页面控制器与外部 API 复用应用服务，不能复制一套业务流程。业务表按功能 PR 增量迁移，不在 PR-01 创建未使用的几十张表。

持久化统一使用 Spring Data JPA 实体、JpaRepository 和服务层短事务，不编写 JdbcTemplate 业务仓储，不创建通用 DAO 包装层。数据库约束、索引与结构由 Flyway 迁移；Hibernate 仅 validate，关闭 Open Session in View。需要 PostgreSQL 原子领取/幂等 SQL 时使用仓储内明确的原生查询与事务边界，不另起 JDBC 持久化体系。

### 2. 业务对象及标识

| 标识/记录 | 用途 | 必须保持的规则 |
|---|---|---|
| callerId | 经过认证的调用方身份 | 从服务端鉴权取得，不信任请求体自报身份 |
| endpointId | 已配置 FTP/SFTP 连接 | 协议、认证、受控根目录及启用状态独立于任务状态 |
| listenerId | 长期扫描配置 | 一个连接可有多个监听；改名称/周期不换身份 |
| sourceId | 稳定来源与单元识别规则 | 可与监听映射；不直接等同 endpointId；无监听的 API 也须解析稳定来源 |
| 外部 taskId | 调用方业务任务号 | 唯一范围为 `callerId + taskId`；跨 XML/JSON 入口保持一致 |
| taskRecordId | 共享平台内部任务记录号 | 用于查询和关联，避免与外部 taskId 混淆 |
| transferId | 某源版本的一轮拉取交付 | 普通重试/补通知沿用；正式重新交付创建新编号并关联上一轮 |
| notificationId | 一份固定通知 | 普通重试沿用编号与原报文字节，不生成不同业务内容 |

任务、产品/数据单元、物理文件分别记录；旧 XML 的 `fileCount` 是产品数，不能当物理文件总数。一次范围拉取可关联多轮交付；多个请求复用同一交付时也需保留关联，而非重复下载。

这些是逻辑记录，不强制“一项一张表”。已存在的任务、单元明细和关联记录应优先复用。

### 3. 最小持久化与事务边界

连接、路由、监听、任务及配置快照、固定清单、文件结果、候选/源版本、交付、通知、回执均需持久化。秘密只保存受控引用或密文，不进入任务明文快照。

新任务和初始状态在事务提交后才能返回受理成功。任务结果与该阶段待发通知在同一数据库事务内保存；后台扫描通知表发送，即轻量 Outbox，不另上消息中间件。网络传输不得持有长数据库事务。

业务数据发布与数据库不属于一个原子事务。必须在发布前保存足以核对的任务、清单摘要和目标位置，发生崩溃时依据固定标识核对外部结果，再补齐状态及通知。目录存在不等于校验通过。

用数据库唯一约束和条件更新领取任务，禁止只“先查后插”或仅用进程内布尔值防重。单实例运行是本版部署约束；不承诺多实例容灾。一个任务同一时刻只有一个有效执行尝试，状态更新须校验版本/领取身份，拒绝迟到写回。

#### 3.1 PostgreSQL 实施约定

数据库类型已由用户指定为 PostgreSQL（F17）。以下环境安排、依赖和测试规则属于本轮 P 类实施方案，不附加用户未指定的主版本、主键形式或外键禁用规则。

| 项目 | 本轮实现规则 |
|---|---|
| 环境 | `local`、涉及数据库的 `test/CI`、`prod` 统一使用真实 PostgreSQL；纯单元测试可不启动数据库。不保留 H2 作为运行库、测试替代库或隐式回退，不扩展 MySQL 兼容层 |
| 版本 | 用户未指定主版本。按实际部署记录与 JPA/Hibernate、驱动和 Flyway 匹配的版本；测试与目标部署主版本保持一致，原生服务版本明确固定 |
| 依赖 | 使用 spring-boot-starter-data-jpa、org.postgresql:postgresql、flyway-core。Boot 2.7 管理的 Flyway 8.5.13 内置 PostgreSQL 支持，不添加新版独立模块；不引入独立 JDBC starter、JdbcTemplate 业务仓储或 Spring Security |
| 连接 | 使用外置 `spring.datasource.url`、用户名和密码；URL 格式为 `jdbc:postgresql://host:port/database`。不在 URL、仓库、页面或日志中暴露口令；缺配置/连接失败明确报错，不启动临时内存库冒充可用 |
| 迁移 | 只编写目标 PostgreSQL 支持的 SQL；按 PR 增量交付 `db/migration` 脚本，验证空库初始化和旧版本升级。已执行迁移不原地改写；不使用清库或删除迁移历史掩盖错误 |
| 本地与 CI | 直接连接本机/专用原生 PostgreSQL，不使用 Docker。CI 直接启动固定版本的原生服务并执行 JPA 仓储和迁移集成测试；无条件时明确失败或未验证，不静默换库 |
| 测试安全 | 数据库测试只能连接显式指定的隔离测试库/实例；校验测试目标后才创建/清理测试对象，禁止默认连接开发或生产数据执行破坏性清理 |

连接参数按 [pgJDBC 官方连接说明](https://jdbc.postgresql.org/documentation/use/) 核对；业务持久化遵循 [Spring Data JPA 2.7.18](https://docs.spring.io/spring-data/jpa/docs/2.7.18/reference/html/)。JPA、PostgreSQL 和直接连接来自用户要求，具体版本及测试隔离方式为实施选择，真实解析/迁移/读写结果见 [PR-01 实施记录](PR-01_实施记录.md)。

#### 3.2 唯一约束与执行领取

请求幂等和规范化交付键必须有 PostgreSQL 唯一约束；组成业务唯一键的必需字段设为非空，可选维度先按明确业务规则规范化，不能靠含 NULL 的普通组合唯一约束假定能够完整去重。相关行为见 [PostgreSQL 约束说明](https://www.postgresql.org/docs/current/ddl-constraints.html)。

并发插入可使用指定幂等唯一键的 `INSERT ... ON CONFLICT (...) DO NOTHING`，再在适当事务可见性下读取并比较已存在的业务内容；不能通过 `DO UPDATE` 无条件覆盖旧任务。采用捕获唯一键异常的实现时，先按事务边界正确回滚，再读取已有记录；不能在已失败事务中继续查询。并发写入者回滚或记录暂不可见时必须有有界重试及明确错误，不虚构幂等成功。语法依据见 [PostgreSQL INSERT / ON CONFLICT](https://www.postgresql.org/docs/current/sql-insert.html)。

领取任务和通知使用带状态/版本条件的短事务更新，更新成功才能开始执行，事务提交后再做文件传输和 HTTP 调用。并发幂等、领取竞争、事务回滚、通知唯一性均在真实 PostgreSQL 上验收，Mock 或其他数据库的结果不能代替。

### 4. 新接口实施契约

以下 URL/JSON 为本轮开发默认设计，不是原接口既有事实。PR-03 提交正式 OpenAPI/示例；PR-04/05 追加方向字段校验。

| 接口 | 用途与约束 |
|---|---|
| `POST /api/transfers/tasks` | 创建 PUSH/PULL；鉴权、路径与配置引用校验、幂等、持久化后异步 |
| `GET /api/transfers/tasks/{taskRecordId}` | 查询本调用方可访问的任务和分维度状态 |
| `GET /api/transfers/tasks/{taskRecordId}/files` | 分页查询文件进度，不一次返回全部大清单 |
| `POST /api/sharing/pull/confirmations` | 验收回执，绑定认证接收方、transferId、sourceVersion |
| 旧 XML 入口 | URL 与内容类型在契约文件中单独确定；经适配复用同一任务服务 |

公共请求包含 `taskId`、`direction`、`endpointId`。PUSH 提供产品清单、受控 sourceRoot 引用及目标根目录内的目标位置；PULL 提供受控源范围及交付配置，或通过 listenerId/sourceId 继承。不能携带任意主机、口令、回调 URL 或绝对路径绕过配置。具体字段一旦锁定即维护回归样例，避免开发者各自起名。

新任务响应建议 `202 + taskRecordId + taskId + accepted=true + executionStatus`；幂等命中返回 `200 + reused=true + 原任务`；同键不同语义返回 `409`；非法请求 `400`，身份/权限错误 `401/403`，功能未就绪 `503 ENGINE_NOT_READY`。这些是 P 类约定，不覆盖旧 XML 接收协议。

请求指纹只比较规范化的业务语义，忽略格式差异及链路 traceId。对重复请求使用原任务保存的默认值与路由解释，不因配置被编辑就让原请求冲突或把目标改到新地址。跨 XML/JSON 的等价请求经相同规范化逻辑比较；不同方向、目标或产品范围必须冲突。

未知 XML 根节点、缺少真实样例的结构不能自行宣布兼容。禁用外部实体、外部 DTD/XInclude，限制报文体积、节点数量与解析深度；报文和错误输出正确转义。

### 5. 三条幂等边界

**请求幂等：** `callerId + externalTaskId` 唯一，同键同内容返回原任务；不同内容拒绝。

**源版本识别：** 候选阶段以稳定来源和路径关联，属性变化重置观察；就绪后冻结 sourceVersion。版本方案及强弱一起保存，弱属性不能承诺发现同大小同时间的所有覆盖。

**交付去重：** 建议键为 `endpointId + 规范化源路径 + 数据单元规则 + 可比较的版本方案及值 + deliveryScope`。deliveryScope 包含稳定目标根目录/映射、业务接收方和要求的校验规则，不包含每轮新生成的 transferId 路径。不同接收方、目的地或校验范围不合并；不同来源版本不可比较时，不推断相同，配置阶段提示并阻止未明确策略的重叠。

上述交付键通过数据库唯一约束维护当前轮次；重交通过原子更新转向新 transferId。原 task 与交付关联保留。触发方式、listenerId 改变不应成为绕过去重的手段。

### 6. 状态维度与成功判据

| 维度 | 典型状态/含义 |
|---|---|
| 连接配置 | ENABLED/DISABLED |
| 连接健康 | UNKNOWN/REACHABLE/UNREACHABLE，并带观测时间 |
| 监听 | 启停单列；IDLE/SCANNING/BACKOFF/ERROR 等运行状态 |
| 执行 | ACCEPTED/PRECHECKING/WAITING_SOURCE/WAITING_FEEDBACK/QUEUED/TRANSFERRING/VERIFYING/PUBLISHING/SUCCEEDED/FAILED/REJECTED/RECONCILING |
| 通知 | PENDING/SENDING/ACKED/RETRY_WAIT/NEEDS_ATTENTION，各阶段分别保存 |
| 拉取验收 | NOT_STARTED/PENDING/ACCEPTED/REJECTED |

枚举可由代码统一命名，但业务含义不可合并。推送技术成功需所有文件满足固定基准并有效发布；闭环还需必需通知的接收确认。拉取最终成功需有效交付技术检查通过且收到验收成功；有效验收不依赖通知 ACK 必须先到。任务聚合不能用一个子项成功代替全部子项成功。

无新增数据的范围任务明确记录 `NO_NEW_DATA` 结果和范围，不虚构 transferId/验收通知。发布结果未知进入 RECONCILING，不抢先报告失败或覆盖成果。

### 7. 完整性、路径与协议

推送固定清单后不再增删清单文件；每个文件比较“预检源内容、上传实际读取内容、目标实际内容”的字节数和 SHA-256。没有远端哈希就完整回读目标文件；只回读哈希文本不能证明业务数据正确。回读权限缺失不能自动降级。

拉取 HASH 必须有绑定源版本的 expectedHash；仅计算本地 actualHash 不算 HASH 校验。BASIC 单独标明保证范围。所有哈希流式计算，字节数使用 long，文件进度持久化节流但阶段变更必须及时落库。

本地路径进行受控根目录解析与真实路径检查；逐级拒绝符号链接、特殊文件及目标冲突，防止检查后路径替换。远端使用协议自身的属性/路径能力；FTP 无法可靠辨别链接时应将隔离账号根目录作为接入条件并暴露能力限制，不虚构严格路径验证通过。任务临时文件与业务文件隔离，避免 `a` 的临时名与合法业务 `a.part` 相撞。

FTP 使用二进制与实际数据通道测试；流式 API 必须等待并验证命令最终完成响应。SFTP 校验可信服务器主机密钥，不能使用无条件接受验证器，不默认执行远端 shell。协议细节仅由适配器实现，业务流程不能混用 FTP 命令。

### 8. 通知、验收和重试

通知按至少一次发送设计；接收端按关联编号与内容去重，不宣称端到端恰好一次。固定通知 ID、业务内容、接收方和协议版本。普通补发不重新上传或下载。

新 JSON 通知建议含 notificationId、taskRecordId、taskId、stage、result；拉取还含 transferId/sourceVersion。JSON ACK 建议 `accepted=true` 且回显对应 notificationId；旧 XML ACK 按联调契约解析。除非对接配置明确约定，不能仅凭 HTTP 2xx 判断已持久化接收。

推送成功预检通知取得约定 ACK 后再传业务文件。预检拒绝只产生拒绝反馈，默认不产生 doComplete。终态完成单保留全部原产品；`status=2` 不用于进行中或普通取消。

回执校验接收方身份、当前交付轮次、源版本及已发布前提。相同回执幂等；矛盾终态记录冲突不覆盖；旧轮次迟到不改新轮次；不同源版本的独立交付仍可分别验收。有效验收先于通知 ACK 时正常接收，并把对应通知标记“业务回执已确认接收”或保留独立状态，不触发重新下载。

文件重试默认首次之外最多 3 次；通知按独立计数、退避和最大尝试数配置。验收超时保持待验收，不自动判失败/成功。认证、主机密钥、路径和配置冲突不做无意义循环重试。

### 9. 配置变更、安全和保留

服务停用拒绝新的 API 任务和新的监听任务；监听停用只关闭周期触发，允许有权限的手动执行一次，不自动恢复监听。已受理任务及其中必要重连按快照继续。改变地址、目录、协议不切换在途任务的目标。

敏感凭据以版本化引用保存，口令可由外置主密钥加密存储，私钥可引用受限服务端文件。配置页面写入新值但不回显原文；在途任务引用旧版本，不能因更新凭据而无说明地改变其身份。不要另建复杂密钥管理系统；备份数据库时记录主密钥的独立备份责任。

页面按用户要求无需登录，不引入 Spring Security。PR-01 只提供只读导航，没有提交表单和业务 API；PR-02 开放写入时提供请求防伪、参数校验、输出转义及操作记录，PR-03 实施外部调用方校验，可使用原生 Servlet Filter，不将其前置成 PR-01 的认证框架。回调和远端地址通过服务端配置限定范围，不跟随未经授权的重定向。源文件、待验收和已发布数据默认保留；临时清理只处理已证明属于平台且无有效任务引用的范围。

### 10. 可验收的进度与测试原则

传输字节、已验证字节、网络重传流量分开统计。重试不加总为已完成业务字节。总量未知显示未知；零字节单元避免除零；传输到 100% 后继续显示校验/发布/验收阶段。

所有涉及真实传输的 PR 都要对真实 FTP 和 SFTP 测试服务执行，不以全 Mock 代替。使用本地嵌入式或专用原生协议服务，不使用 Docker，也不调用客户地址。业务接收方可用明确标注的本地 HTTP 测试服务验证 ACK 和回执。时钟、重试间隔可注入，测试不通过长时间 sleep 模拟稳定窗口。

参考：[Spring MVC + Thymeleaf](https://spring.io/guides/gs/serving-web-content)、[Apache FTPClient](https://commons.apache.org/proper/commons-net/apidocs/org/apache/commons/net/ftp/FTPClient.html)、[Apache MINA SFTP](https://github.com/apache/mina-sshd/blob/master/docs/sftp.md)。这些是实现参考，不构成新增用户需求。

## PR-02｜FTP/SFTP 连接配置与真实能力探测

| 项目 | 内容 |
|---|---|
| 建议标题 | `feat: configure FTP and SFTP endpoints with capability checks` |
| 建议分支 | `codex/pr-02-endpoints` |
| 前置 | PR-01 已合并并通过验收 |
| 需求映射 | F06、F07、F09；A07；支撑 A01/A02/A03；D03、D07、D09 |
| 状态 | 已在工作区实施；本地 36 项测试通过，未提交远端；见 [实施记录](PR-02_实施记录.md) |

### 1. 目标

配置页可以新增、修改、启停多个 FTP/SFTP 连接，保存后重启不丢失；真实检测认证、目录和本任务需要的读写、校验、重命名能力。向后续任务提供统一协议适配边界。

### 2. 数据、配置与页面

连接字段至少含 endpointId、名称、协议、主机端口、用户名、认证方式、凭据引用/密文、允许的远端读写根目录、允许的本地源/目标根目录引用、超时、并发上限、启用状态、配置版本及最近检测结果。

FTP 参数与 SFTP 参数分开校验。FTP 默认二进制，被动模式作为初值可配置；SFTP 支持按接入条件选择密码或私钥，必须配置可信主机密钥/指纹。私钥文件只允许引用管理员约定的受限目录，不允许接口随意读取系统文件。

实现新增/编辑、启停、检测和列表。表单秘密字段留空表示保留原值，清除凭据需独立明确操作；列表、详情和日志不显示秘密。历史引用保护、版本化凭据和任务快照按公共约定设计；当前可只做停用，不提供破坏历史记录的硬删除。

### 3. 协议适配边界

新增小型 `RemoteFileClient` / factory：连接、列举、lstat/stat、读取、写入、创建目录、重命名、删除平台临时文件、能力查询和关闭。业务层传入已解析的受控路径与流，不依赖 FTPClient 或 SFTP 的具体类型。

FTP 使用 Apache Commons Net，SFTP 使用 Apache MINA SSHD；锁定实际可解析且与 JDK 兼容的正式版本。单任务独占其会话，所有异常路径关闭连接和文件句柄。不实现泛化插件市场或运行时加载框架。

FTP 流读写结束必须检查最终完成响应；不能只把流关闭当作成功。SFTP 等待读写关闭结果，不发送 FTP 的 TYPE/SIZE/被动模式命令。无条件接受所有 SSH 主机密钥的实现禁止提交。

### 4. 能力探测

| 检测 | 方法与边界 |
|---|---|
| 连接/认证 | 使用配置的协议连接，区分 DNS/连接超时、认证、主机密钥失败 |
| 读取 | 在授权路径列举、读取指定测试对象；不能以登录成功替代 |
| 写入 | 仅在有写权限且明确指定的探测子目录写入非空随机文件 |
| 完整性 | 实际远端大小/哈希能力，或完整回读探测文件比对；无哈希能力可使用回读 |
| 重命名 | 在独占探测范围验证操作结果，失败单独记录 |
| 清理 | 仅删除本次探测创建且归属明确的文件/目录；失败记录残留路径 |
| 容量 | 能获取则记录实际值；无法获取显示 UNKNOWN，不能填“充足” |

只读拉取连接不因无法写探测文件而判定不可用；其 `canRead=true, canWrite=false` 合法。只写且不可回读、无可信远端哈希的连接可保存，但标明“不满足严格推送条件”，不得标成可严格推送。

检测有明确超时和有界并发；不在 HTTP 请求线程无限等待。检测结果显示时间与配置版本；编辑连接后旧结果标过期。本次检测结果不能免除每个任务的必要预检查。

### 5. 修改范围

新增 endpoint/protocol 服务、JPA 实体与仓储、配置表迁移、`templates/config/endpoints*`、协议测试夹具和测试。沿用 PR-01 页面布局，不新增登录或 Spring Security；表单写入增加请求防伪与参数校验。测试仅用临时目录和非生产凭据，不访问客户地址。

### 6. 验收与测试

## PR-03｜统一任务入口、幂等、持久化执行与通知基础

| 项目 | 内容 |
|---|---|
| 建议标题 | `feat: add durable task intake and notification dispatch` |
| 建议分支 | `codex/pr-03-task-core` |
| 前置 | PR-01、PR-02 |
| 需求映射 | F02、F03、F07；I01—I08；支撑 A03、A04、A08；D07、D09 |
| 状态 | 待实施；所有测试未执行 |

### 1. 目标与阶段边界

建立两种入口共用的任务接收、幂等、状态、查询、执行领取和通知机制。业务传输由后续 PR 接入，本 PR 不用空实现返回传输成功。

生产运行中，PUSH/PULL 处理器未安装的方向返回 `503 ENGINE_NOT_READY`，不先持久化一个永远没人处理的任务。测试环境使用明确的测试处理器验证任务框架，不把该处理器装配到生产。

### 2. 任务入口与鉴权

实现公共约定中的新任务和查询接口。callerId 由认证身份取得；调用方仅能使用已授权 endpoint、源/目标根目录、监听/来源和固定通知配置。接口禁止接受任意主机、口令、回调 URL。

区分外部 taskId 与内部 taskRecordId。保存来源、入口类型、方向、规范化请求摘要、必要原始报文、配置快照、时间、阶段、错误和版本号。原报文限制长度并脱敏，按访问权限保留，不写入普通日志。

缺少可识别任务号、认证失败、报文无法解析等同步拒绝。已能受理的业务任务，其文件数量、路由和源文件检查由具体预检查处理器反馈；不能把“请求持久化成功”当作“检查通过”。

### 3. 请求幂等与快照

数据库唯一键为 `(callerId, external_task_id)`。同键同规范化业务内容返回原任务；不同内容返回 409，不改原记录。在 PostgreSQL 使用针对该唯一键的 `ON CONFLICT DO NOTHING` 后读取并比较已有任务，或采用正确回滚边界处理唯一键冲突；遵守公共约定第 3.2 节，不能在失败事务中继续查询，也不能无条件更新旧请求，不放大为第二个执行。

跨 XML/JSON 统一成同一内部命令。规范化字段包含方向、产品集合、原路径解释和目标选择，忽略 XML 空白/属性顺序等非业务差异。重复请求使用最初记录的默认值和路由快照比较；后台配置变化不重新路由原任务。

快照至少覆盖 endpoint 版本、协议、受控目录、稳定接收方/交付范围、通知契约、来源规则与秘密版本引用。受理后编辑配置不让在途任务换协议、换地址或换校验模式。

### 4. 执行与状态基础

实现集中状态迁移服务、任务仓储、有界执行器、数据库原子领取和可重试任务的 nextRunAt。HTTP 线程只做接入事务，不执行扫描/哈希/上传。线程池满时任务留在持久化队列，不能丢任务或无限创建线程。

任务执行、通知、验收分维度保存。状态更新有前置状态、版本/领取身份校验，重复事件不倒退终态。不要为状态枚举引入外部工作流系统。

任务查询分页返回产品/文件/交付摘要；文件明细走分页接口。未冻结清单时总字节数为未知，不填 0 冒充空任务。内部失败异常分类为网络临时错误、权限/路径、配置、源变化、校验不符、发布未知等，保留可定位原因。

### 5. 持久化通知

实现 notification/outbox 记录：notificationId、任务/交付关联、阶段、协议、接收方配置快照、固定报文、内容摘要、发送次数、nextAttemptAt、状态、ACK 和最后错误。

阶段结果与通知一起提交；通知执行器分批领取、发送、验证关联 ACK、更新结果。超时及响应丢失按同编号/同报文重发。一个阶段只有一份有效结果通知，禁止同任务同时新增含义矛盾的成功/失败通知。

发送有超时与有限退避；超过自动次数后保留 NEEDS_ATTENTION。发送 HTTP 请求时不持有业务长事务。验证 ACK 身份/关联字段；错误任务号、错误通知号或仅返回 2xx 不能在未约定情况下标送达。

### 6. 旧 XML 适配与暂定契约

保留旧任务通知单、doAsk、doComplete 的适配边界。已知规则必须落实：fileCount=product 数量；product 为产品包；产品 ID 的原文长度约束；rejectrason 原拼写；doAsk 0/1；doComplete 0/1/2；完成单保留原产品全集。

实际 XML 样例、根节点、ProductList/productList 唯一结构、提交方式和 ACK 未全部确定。把开发用样例放入 `doc/contracts/provisional/` 并标注“待联调”，配套测试只能证明该暂定契约。不要同时输出两份产品列表，不声称已与客户 XML 兼容。

### 7. 修改与交付

新增 transfer 核心、统一 API、XML 适配、notification、仓储迁移和测试；数据库优先包含任务、必要产品明细、通知及关联记录。清单/文件明细由 PR-04 增量补齐，来源/交付由 PR-05 补齐。

| 接入和持久化 | 鉴权、安全解析、任务幂等、持久化后受理 |
| 请求和路由 | 必填项、产品数/ID、唯一且启用的路由、调用权限 |
| 路径和集合 | 源目录真实路径、重复/包含范围、符号链接/特殊文件、目录和目标映射冲突 |
| 源可读与固定 | 实际逐文件读取；配置的临时名/零字节规则；流式大小和 SHA-256；读取前后属性及整目录复查 |
| 清单 | 产品全集、目录结构、物理文件路径/大小/hash、清单版本与固定摘要持久化 |
| 目标条件 | 两种协议实际操作能力、严格验证路径、独占目标目录冲突、已知容量情况 |

清单冻结失败不进入可执行状态。没有上游预期清单时仅保证观察到的固定集合，不能声称检查出未知漏生成文件。

预检结果与待发反馈同事务保存。成功反馈取得约定 ACK 前保持 WAITING_FEEDBACK，不发送业务文件；探测文件不是业务交付。拒绝反馈使用 doAsk result=1/rejectrason 或新 JSON 同义契约，默认不再发 doComplete。

### 4. 文件传输与严格验证

执行前再次确认固定源及状态，领取唯一执行资格。使用任务快照与协议适配器，在本任务独占区域写临时文件；临时命名不能撞上合法业务文件。

每个文件必须满足：

```text
预检清单大小 = 上传实际读取字节数 = 目标实际字节数
预检清单SHA-256 = 上传读取摘要 = 目标实际内容摘要
```

目标没有远端哈希时通过 FTP/SFTP 完整回读目标文件计算摘要；不可只回读自己上传的 `.sha256` 文本。不支持远端哈希且不能回读的服务拒绝严格推送。大文件流式读取，不整体放入内存。

目标通过验证后发布单文件正式名，核对改名结果并记录已验证。网络中断按单文件有限重试，未完成文件首版从头传；已验证文件只能在重新核对固定基准后复用。源变化立即终止旧任务，不重新生成清单继续放行。

### 5. 整单发布与未知结果

全部文件结束后复核源和目标集合、目录、原产品全集、逐文件核验记录及临时残留。任一必需项缺失，不发布 `_READY`。

固定生成 `_manifest.xml` 字节与摘要，先上传并核验清单，再发布绑定 taskId、清单摘要和产品数的 `_READY`。标记本身先写临时名，最后发布并读回核对。接收方只消费有效标记及匹配清单；该规则要在外部联调确认。

标记写入/改名响应丢失时进入 RECONCILING，读取实际标记和清单定位结果。没有核清前不得发送失败完成单、重建原目标或发布相反结果。记录发布前意图使 PR-08 能测试所有崩溃窗口；本 PR 已须有正常核对路径，不能把关键保护延后。

### 6. 完成反馈与状态

确认成功后保存执行成功及固定完成通知，原 XML status=0。确认执行失败且未有效发布时 status=1；status=2 保留作废删除语义，本 PR 不实现未约定的删除操作。

完成单保留原 product 全集与原 fileCount，失败和未执行产品也在其中。目标 productPath 按约定返回相对 targetRoot 的交付位置；失败路径仅供诊断。通知失败只补通知，执行成功不回退失败。

记录上传、目标验证、发布、等待通知各阶段及实际进度。上传字节 100% 不等于整单成功；回读流量单列。源路径、目标路径和错误只向授权管理者/调用方展示。

### 7. 修改与交付

实现 push 业务、固定清单与文件明细迁移、路由最小配置、清单/标记序列化、双协议测试及回调样例。使用 PR-03 的任务/通知/状态机制和 PR-02 协议适配器，不复制第二套。

## PR-05｜API 单次拉取、源版本、技术检查与业务验收

| 项目 | 内容 |
|---|---|
| 建议标题 | `feat: support one-shot pulls with verification and acceptance receipts` |
| 建议分支 | `codex/pr-05-pull` |
| 前置 | PR-01—PR-04 |
| 需求映射 | F01、F05、F07；A02、A06；D05、D07、D09 |
| 状态 | 待实施；所有测试未执行 |

### 1. 目标

开放统一任务入口的 PULL 方向：对 FTP/SFTP 的指定文件、产品目录或受控扫描范围执行一次拉取，完成就绪判断、版本去重、下载、校验、待验收发布、通知和有效回执处理。单次调用不创建长期监听。

### 2. 来源规则与单次任务

来源配置至少含稳定 sourceId、endpoint、源根/范围、unitType、产品目录层级/文件匹配、就绪规则、校验级别、落地目标、业务接收方、访问映射和通知契约。先提供最小来源配置，PR-06 为其增加 listenerId/扫描周期关联，不换来源身份。

unitType 明确为 FILE 或 PACKAGE_DIR，不按后缀猜测。源的压缩包按普通文件传输，除非来源已有明确结构检查规则，不自动解压。

当前尚未就绪的 API 任务进入 WAITING_SOURCE，由任务自己的 nextRunAt 重查直至就绪或等待处理；此重查属于本次任务生命周期，不生成永久 listener。若引用 listenerId，由 PR-06 接入后校验 endpoint 关联及继承权限。

### 3. 候选、版本与交付去重

发现后立即持久化候选。有效扫描中集合/属性变化时更新候选并重置稳定次数；失败或部分扫描不增加稳定次数。满足来源就绪条件后再冻结 sourceVersion、固定本次文件集合和源端校验基准。

优先使用源端不可变版本或绑定清单摘要；大小/修改时间属于弱识别，记录 versionBasis 和强弱，不夸大覆盖发现能力。

实现公共约定的交付唯一键和原子领取，去重范围包含稳定交付位置、接收方和要求的校验规则。正在下载、通知重试、待验收或已接受的相同交付应复用并建立任务关联；不能因新 API taskId 又下载一次。不同消费方/落地目标分别交付。

一个任务范围有多个数据单元时分别分配/关联 transferId，逐单元独立处理。未就绪单元不妨碍其他已就绪单元；任务展示每项状态。所有必需单元验收成功才为整体成功；尚有处理中单元时保留处理中/部分失败信息，全部结束且存在最终失败时聚合为失败。无新数据明确 NO_NEW_DATA，不构造空交付。

### 4. 下载与技术检查

在 `tmp/transferId/` 隔离下载，按固定集合执行。写入完成且关闭后检查实际落盘大小；HASH 模式对落盘实际文件流式计算摘要并与绑定源版本的 expectedHash 比较。BASIC 保存 actualHash 供追溯，但 expectedHash 为空时不能宣布 HASH 通过。

严格 HASH 缺基准时保持不可执行并给原因，不自动降级。下载后复查源版本、属性及集合；发现变化终止旧基准交付，返回新候选观察，不拼接新旧内容。

网络临时故障有限重试，首版未完成文件整文件重下。业务不合格的同一份源数据不得无限重下。控制文件和业务文件分别统计；符号链接、越界、特殊文件拒绝。

### 5. 待验收发布与结果通知

技术检查全部通过后，发布到稳定的 `pending/transferId/`。优先同文件系统受控移动；无法原子移动时使用明确完成标记和接收规则，不能暴露半成品。发布前持久化用于恢复的清单、摘要与意图，完成后保存已发布事实及待发通知。

dataLocation 必须来自配置的业务可访问映射，不直接把共享平台的本机绝对路径当作对方可访问地址。发布后直到验收/保留处置，路径和内容不变；接收方验收成功也不自动删除或移动。

成功通知含 transferId、sourceVersion、unitType、实际文件数/字节数、校验等级与真实校验信息、有效 dataLocation。最终传输失败通知含原因，不带有效 dataLocation/已通过等级，也不开始业务验收。通知失败只补通知，不重下。

### 6. 验收回执与重新交付

实现 `POST /api/sharing/pull/confirmations` 的本轮 JSON 契约，旧/其他 XML 形式仅通过显式适配接入。验证认证接收方、transferId、sourceVersion、当前交付轮次，以及该交付已经技术通过并发布。

有效成功回执转 ACCEPTED；有效失败回执转 REJECTED 并保存原因/分类。回执先于通知 ACK 到达仍正常处理，不能因本地尚无 ACK 就拒绝已经有效的验收结果。

相同回执返回已接收；冲突终态记录协议冲突不覆盖。已被新轮次替代的旧 transferId 只记历史；不同源版本的有效旧交付仍独立可验收。验收超时保持 PENDING 并记录提醒，不自动成功或把它当传输失败。

实现受控的“新交付轮次”服务方法，用于明确修复后的重新交付：新 transferId、原子更新当前轮次关联、保留历史、重新检查源基准。普通通知重试和传输内部重试不能调用它；本 PR 不需要增加任意重跑按钮。

### 7. 修改与交付

新增 pull 服务、候选/版本和交付持久化、任务-交付关联、验收接口与记录、来源最小配置及访问映射校验。复用任务、通知、协议、哈希和路径能力，避免创建第二套状态/重试框架。

### 8. 验收与测试

| 编号 | 场景 | 预期 |

## PR-06｜多目标定时监听、独立扫描与跨入口去重

监听字段包含 listenerId、名称、endpointId、稳定 sourceId/规则版本、源范围、数据单元与识别规则、就绪规则、校验等级、稳定交付目标和接收方、周期、初次扫描模式、启用状态、最近/下次扫描时间和最近结果。

来源内容直接复用 PR-05 配置，不在监听里另建一份互不一致的来源解析器。编辑名称、周期、超时不换 sourceId，不清空历史。修改源根、单元边界、交付范围时创建配置版本，明确继承或重扫范围并展示影响，不静默把所有旧文件变成新增。

### 3. 调度与就绪观察

使用数据库存储扫描计划、运行记录和候选观察，由轻量定时触发器检查到期监听。每轮原子领取，同一监听上一轮未完成时跳过/合并并记录原因，不能累积无限触发。

调度触发、目录扫描与文件传输不能共用一个被大文件占死的线程。设置有界扫描池和传输池、全局及每 endpoint 配额；无额度时持久化排队。加公平调度，不能让高频失败或大目录监听长期占满全部名额。

开发初值：扫描间隔 60 秒、连续 3 次有效一致观察、最小观察时长 120 秒，均为 P 类可配置初值。只有完整成功的扫描能计数，部分目录失败不能当文件已删除。生产方标记/清单优先，稳定观察只是兼容就绪条件，不是生产完整性证明。

使用可注入时钟测试周期和观察窗口，不通过等待几分钟制造测试通过。记录每轮范围、候选/新版本数量、创建或复用任务数量、错误和耗时。

### 4. 初次扫描

默认 IMPORT_EXISTING，处理当前范围尚未交付的数据。明确选择 BASELINE_ONLY 时，首次完整有效扫描只登记历史基线，不创建下载交付；保存初始化选择、时间与范围。初始化失败不能把部分结果标成完整基线，后续继续初始化并可诊断。

基线只影响对应监听/来源的既定交付范围，不能把另一接收方应拿到的数据全局标成已处理。后续新版本照常处理。禁用再启用、重启、修改周期均不能重新偷偷基线化而漏数据。

### 5. 与 API、重叠监听的去重

所有触发进入同一候选/版本/交付服务，记录 triggerType 和所有触发关联。API 引用 listenerId 时校验 endpoint 一致，路径不得扩大授权范围；停用的监听可提供配置给有权限的单次调用，但不恢复定时。

跨监听按公共约定的规范化交付键和数据库唯一约束竞争，不能只按各自 listenerId/sourceId 加锁。若版本算法不可比较或规则不同而不能安全判断是否同一交付，保存配置时提示冲突并要求明确范围策略，不能猜测去重。

同内容同版本同接收范围复用交付；不同接收方/落地目标/校验要求分别交付。等待就绪、失败、通知待补和待验收记录均复用原处理关系；每一轮扫描不能创建一条新失败记录掩盖同一问题。

### 6. 重启与停用

监听配置、初始化状态、候选次数、最小观察起点、版本历史和 nextRunAt 持久化。进程重启后按启用状态恢复调度，先核对中断扫描，不清空去重历史。

错过的周期首版合并为一次补扫，不为每个错过时点补出任务洪峰。停用仅影响后续触发；已受理单次任务、已存在的下载和验收继续按原快照。

### 7. 修改与交付

新增 listener 配置/页面、扫描计划及记录迁移和调度器。复用 PR-05 的来源、就绪、下载、交付与回执，不复制文件处理实现。用两个以上真实协议测试服务/目标证明独立运行与去重。

### 8. 验收与测试

监听计划、候选、源版本和交付记录均使用 PostgreSQL；重叠监听/API 并发竞争与重启持久化必须在真实 PostgreSQL 上验证，不能以进程内集合或 H2 结果代替。

| 编号 | 场景 | 预期 |
|---|---|---|
| 06-T01 | 一个 FTP、多目录监听，加一个 SFTP 监听 | 各自目录/周期/状态正确，可独立启停 |

## PR-07｜当前服务、监听运行、任务详情与安全运维操作

| 项目 | 内容 |
|---|---|

整合已经实现的连接、监听和任务能力，使操作人员能够在同一 Java 应用内配置服务、查看当前运行情况、定位具体失败阶段，并执行有限的安全操作。PR-02/06 已有可用配置页，本 PR 不推倒重做。

### 2. 页面范围

| 页面/区域 | 必须展示 |
|---|---|
| 配置 | 连接、源/路由、监听及必要通知绑定；受控目录、规则版本和配置校验 |
| 当前服务 `/services` | 名称、协议、启用状态、最近连通观测及时间、检测原因、关联监听和任务 |
| 监听运行 | 启停与运行状态分别显示，最近/下次扫描、范围、发现/复用统计、失败原因 |
| 任务列表 `/tasks` | 外部/内部任务号、方向、协议、来源、阶段、开始时间、文件/字节摘要、通知/验收状态 |
| 任务详情 `/tasks/{taskRecordId}` | 快照、产品/单元、transferId、逐文件进度、技术验证、发布状态、错误、通知和验收时间线 |

任务列表支持按方向、服务、状态和时间过滤及分页。服务没有任务也要显示；历史任务引用已停用配置仍能查看。详情基于任务快照展示实际执行目标，不能用连接当前配置覆盖历史。

### 3. 状态与进度显示

分别显示配置启用、连接健康、监听运行、任务执行、通知和验收，不压成一个“正常/异常”。最近健康观测显示时间，陈旧结果注明，不把一次错误解释为远端进程停止。

进度至少包含总业务文件数、已传/已验证文件数、总业务字节、当前有效传输/已验证字节、当前文件、重试次数、当前阶段和耗时。已传字节与回读校验流量分开；重试回退当前文件进度，不能累计到超过 100%。

总量未知显示“扫描/预检查中，待确定”，零字节文件防除零。传输达到 100% 时继续显示“目标核验中”“发布中”“待业务验收”等实际阶段；不把进度条当终态。

状态示例必须正确呈现：

| 后台事实 | 页面文案示例 |
|---|---|
| 推送已有效发布，完成单未 ACK | 交付成功，完成通知待送达 |
| 拉取技术通过，未验收 | 下载及技术检查通过，待平台验收 |
| 源就绪条件未满足 | 等待源数据就绪，并显示原因/下次检查 |
| READY 写入结果未知 | 发布结果待核对，不显示明确失败 |
| 有子单元被拒，其他仍处理 | 部分单元失败，其他单元处理中 |

速度只显示真实采样值，没有有效采样显示未知。预计剩余时间首版可不显示，不伪造稳定精确值。文件列表、日志及通知明细分页，避免一次渲染数万行。

### 4. 刷新与页面实现

Thymeleaf 服务端渲染，轻量 JS 调用同应用只读接口刷新，默认 2 秒可配置；页面隐藏时降低/停止轮询，关闭页面停止请求。网络故障显示“状态暂未刷新”，保留最后更新时间，不清空成成功或离线。

所有状态源于任务服务/持久化记录，不能通过定时器自行增加进度。接口返回精确大字节值时避免 JS 数字精度导致溢出，可使用十进制字符串/格式化值。资源本地打包，不加入独立前端部署链。

### 5. 首版操作与边界

允许：连接/监听启停、重新检测、监听执行一次、补发指定未确认通知、触发待核对任务的结果核对。每项操作经过权限、CSRF、当前状态检查及操作记录，双击/并发请求不能产生重复执行。

补发通知沿用固定报文和 notificationId，不重传文件；已确认通知默认不重复发送。触发核对只查询和恢复可证实的状态，不提供任意“强制成功”。同一终态失败内容的重新交付依照 PR-05 受控服务另行处理，不做通用“重跑一切”按钮。

不提供未经约定的任务暂停、取消、源文件删除、批量清理或任意状态编辑。停用连接的确认提示明确“停止新任务，在途任务按原快照继续”，不能误导为停止远端 FTP 服务。

### 6. 错误、权限与审计

错误展示阶段、错误码、可定位的文件/交付、首次/最近时间、有限重试次数及当前处理建议；敏感堆栈只在受控日志，不显示账号口令、私钥和令牌。用户输入和文件名输出转义，拒绝 XSS。

管理操作记录操作者、对象、前后状态、时间与结果即可，不扩展审计平台。任务 API 按调用方隔离，不能只隐藏页面链接却放开查询接口。

### 7. 验收与测试

## PR-08｜故障恢复、端到端联调、部署与首版放行

| 项目 | 内容 |
|---|---|
| 建议标题 | `test: harden recovery and document end-to-end deployment acceptance` |
| 建议分支 | `codex/pr-08-release-validation` |
| 前置 | PR-01—PR-07 |
| 需求映射 | 回归 F01—F17、I01—I08 与 A01—A15；D09；相关 Q 的联调结论 |
| 状态 | 待实施；所有测试未执行；不代表版本已可上线 |

### 1. 目标

验证已实现功能在真实协议服务、数据库持久化和进程中断下能正确恢复，修复影响首版交付的问题，给出可执行部署说明及诚实的放行结论。前序 PR 应已有单元/集成测试，本 PR 不从零补一套表面测试。

### 2. 恢复扫描与不变量

单实例启动后先识别前次中断记录，结合原配置快照、清单、源版本和外部实际状态恢复，不把所有 RUNNING 一律改成 QUEUED。

| 中断位置 | 恢复要求 |
|---|---|
| 预检结果已保存、反馈未 ACK | 恢复原反馈，未 ACK 不开始业务上传 |
| 上传/下载半途 | 核对固定基准，清理/重传本任务未完成文件，保留安全可复用文件 |
| 文件已传完、验证未记录 | 重新验证实际文件，不凭存在/大小认定全部通过 |
| 远端标记已生效、本地成功事务未提交 | 核对标记与清单后恢复发布成功，补齐唯一完成通知 |
| 标记是否生效仍未知 | 保持 RECONCILING，有界重查和待处理提示，不发相反终态 |
| 拉取文件发布、本地通知事务未完成 | 依据事先持久化的清单/意图与实际数据核对后恢复，不创造新交付 |
| 执行成功但通知未确认 | 只重发固定通知，不读写业务文件 |
| 拉取等待验收 | 原路径/transferId 保持，恢复等待，不重新下载 |
| 回执已提交但响应丢失 | 重复回执返回原结果，不改变终态 |
| 监听扫描中/错过周期 | 保留候选/基线/去重历史，合并补扫，不堆积历史触发 |

恢复任务也遵守原子领取和并发限额。源已变化、权限/主机身份变化、目标冲突按明确错误处理，不为“自动恢复”绕过检查。旧执行尝试的迟到写回必须被版本/领取身份拒绝。

### 3. 故障注入与真实链路

使用隔离 FTP、SFTP、PostgreSQL 和本地业务接收端组成测试环境。PostgreSQL 与目标部署主版本一致，记录数据库、JDBC、Flyway 的实际版本；不得以 H2、内存数据或其他数据库通过结果替代。采用测试钩子、代理或受控进程终止复现故障；客户地址不进入自动化测试。测试接收端可模拟已持久化后丢 ACK、提前发送验收、延迟/重复/冲突回执。

在关键数据库提交前后、外部写入前后分别注入故障，不能只做一次“重启后还能打开网页”。每个测试核对数据库记录、传输次数、固定内容摘要、目标目录/标记和通知记录，避免只看最终 HTTP 状态。

### 4. 容量、并发和安全回归

覆盖同一 taskId 并发重复提交、多监听重叠、通知/执行线程池耗尽、扫描部分失败、目标空间不足、读写超时与无数据进展、SFTP 身份变化及敏感日志。

负载参数明确标注为测试配置，不冒充用户规模要求：默认准备至少 1,000 个小文件和一个不小于 256 MiB 的二进制文件；环境不足时可下调但必须报告实际负载和未验证上限。记录运行环境、峰值内存、线程/连接数量、吞吐及失败率，不承诺未经实测的性能指标。可追加超过 2 GiB 的单文件验证 long/客户端边界，未测不得声称大文件上限已验证。

备份和恢复同时覆盖数据库、任务数据目录、凭据版本/外置主密钥引用以及配置。恢复后不能因数据库版本落后而覆盖已发布数据；必须执行发布核对。

### 5. 部署交付

交付可执行 JAR、配置模板、数据库迁移、启动/停止示例与日志位置。提供单机部署说明，涵盖 Java 版本、环境变量、PostgreSQL 具体版本及 JDBC/Flyway 兼容验证、外置连接参数和数据库备份恢复、源/临时/待验收目录权限、出站连接、回调入站、FTP 数据端口条件和 SFTP 可信身份登记。

服务启动不得默认暴露管理功能到公网。HTTPS/可信网络边界按环境明确，普通 FTP 的接入网络风险记录到部署约束；不得未经需求加入 FTPS 取代已有协议。

部署时先停止创建新任务，再等待或记录在途状态，备份后升级，完成数据库迁移和恢复核对。回退前检查数据库兼容性；没有安全逆向迁移时给出恢复备份与外部成果核对步骤，不运行 DROP 清空数据“解决问题”。

记录关闭应用后哪些临时/待验收/已发布数据保留，以及禁止自动清理的范围。验收数据与生产目录物理隔离，脚本不能包含指向客户路径的破坏命令。

### 7. 核心恢复验收用例

| 编号 | 故障/操作 | 放行条件 |
|---|---|---|
| 08-T01 | 持久化后立即杀进程 | 恢复同一任务，不丢、不建重复执行 |
| 08-T02 | 文件传到一半断网/终止 | 受控重试，源变化不混传，无虚假校验成功 |
| 08-T03 | 目标同大小篡改 | 两种协议均识别，不发布成功 |
| 08-T04 | READY 生效后、数据库提交前终止 | 恢复同一发布结果，只补通知 |
| 08-T05 | READY 结果不可查询 | 待核对，有界处理，不先发失败再发成功 |
| 08-T06 | 拉取发布后、通知落库前终止 | 原交付恢复，有效路径可读，补齐唯一通知 |
| 08-T07 | 已收到通知但 ACK 丢失 | 同报文重发，业务文件没有再次传输 |
| 08-T08 | 待验收重启、回执先到或重复 | 原 transferId 和路径不变，回执规则正确 |
| 08-T09 | 旧轮次迟到/矛盾终态 | 不污染当前轮次，不静默回退 |
| 08-T10 | API 与多个监听同时命中 | 同范围一个交付，不同范围分别交付 |
| 08-T11 | 队列耗尽、一个目标持续超时 | 有界资源、任务不丢、其他目标继续 |
| 08-T12 | 修改配置/启停/升级重启 | 历史快照和去重记录保持，停用不误取消在途任务 |
| 08-T13 | 未授权接口、CSRF、XXE、路径/链接、日志 | 无越权、外部实体访问或秘密泄露 |
| 08-T14 | 备份恢复与版本回退演练 | 数据、主密钥责任明确，外部成果核对正确 |

以上恢复场景必须覆盖真实 FTP 与 SFTP；某个协议未跑则记“未验证”，不能借用另一个协议的通过结果。

### 8. 需求验收与最终报告

建立 A01—A15 逐项证据表：需求编号、测试用例、环境、命令、实际结果、证据路径、未验证原因。结果只能使用“通过/失败/未验证/不适用并说明依据”，不能把复选框存在当通过。

最终报告分三层结论：代码构建和自动化测试是否通过；隔离真实协议环境是否通过；客户外部环境是否已经联调。允许写“内部验收通过，外部接口仍待确认”，不得写成“整体已验收上线”。

以下任一项存在，不放行生产：同任务重复执行、目标内容未严格核验即成功、缺 READY 仍可被消费的接收约定缺口、通知失败触发重传、无有效回执自动判拉取成功、重启丢失任务/去重、未知发布结果被强制终态、关闭主机校验/明显越权、关键外部协议未确认。
