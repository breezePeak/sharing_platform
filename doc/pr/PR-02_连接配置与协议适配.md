## 1. 目标

配置页可以新增、修改、启停多个 FTP/SFTP 连接，保存后重启不丢失；真实检测认证、目录和本任务需要的读写、校验、重命名能力。向后续任务提供统一协议适配边界。

## 2. 数据、配置与页面

连接字段至少含 endpointId、名称、协议、主机端口、用户名、认证方式、凭据引用/密文、允许的远端读写根目录、允许的本地源/目标根目录引用、超时、并发上限、启用状态、配置版本及最近检测结果。

FTP 参数与 SFTP 参数分开校验。FTP 默认二进制，被动模式作为初值可配置；SFTP 支持按接入条件选择密码或私钥，必须配置可信主机密钥/指纹。私钥文件只允许引用管理员约定的受限目录，不允许接口随意读取系统文件。

实现新增/编辑、启停、检测和列表。表单秘密字段留空表示保留原值，清除凭据需独立明确操作；列表、详情和日志不显示秘密。历史引用保护、版本化凭据和任务快照按公共约定设计；当前可只做停用，不提供破坏历史记录的硬删除。

## 3. 协议适配边界

新增小型 `RemoteFileClient` / factory：连接、列举、lstat/stat、读取、写入、创建目录、重命名、删除平台临时文件、能力查询和关闭。业务层传入已解析的受控路径与流，不依赖 FTPClient 或 SFTP 的具体类型。

FTP 使用 Apache Commons Net，SFTP 使用 Apache MINA SSHD；锁定实际可解析且与 JDK 兼容的正式版本。单任务独占其会话，所有异常路径关闭连接和文件句柄。不实现泛化插件市场或运行时加载框架。

FTP 流读写结束必须检查最终完成响应；不能只把流关闭当作成功。SFTP 等待读写关闭结果，不发送 FTP 的 TYPE/SIZE/被动模式命令。无条件接受所有 SSH 主机密钥的实现禁止提交。

## 4. 能力探测

| 检测 | 方法与边界 |
|---|---|
| 连接/认证 | 使用配置的协议连接，区分 DNS/连接超时、认证、主机密钥失败 |
| 读取 | 在授权路径列举、读取指定测试对象；不能以登录成功替代 |
| 写入 | 仅在有写权限且明确指定的探测子目录写入非空随机文件 |
| 完整性 | 实际远端大小/哈希能力，或完整回读探测文件比对；无哈希能力可使用回读 |
| 重命名 | 在独占探测范围验证操作结果，失败单独记录 |
| 清理 | 仅删除本次探测创建且归属明确的文件/目录；失败记录残留路径 |
| 容量 | 能获取则记录实际值；无法获取显示 UNKNOWN，不能填“充足” |

只读拉取连接不因无法写探测文件而判定不可用；其 `canRead=true, canWrite=false` 合法。只写且不可回读、无可信远端哈希的连接可保存，但标明“不满足严格推送条件”，不得标成可严格推送。

检测有明确超时和有界并发；不在 HTTP 请求线程无限等待。检测结果显示时间与配置版本；编辑连接后旧结果标过期。本次检测结果不能免除每个任务的必要预检查。

## 一、连接配置从数据库做到页面

实现连接的持久化模型、仓储、应用服务和配置页面。逻辑字段至少包括：

- endpointId、名称、FTP/SFTP 协议、主机、端口、用户名、启用状态和配置版本。
- 认证方式、凭据引用或密文；SFTP 的可信主机密钥/指纹、私钥引用及必要口令。
- 允许的远端读取/写入根目录、受控本地源/落地根目录引用。
- 连接超时、无进展超时、并发上限；FTP 的数据连接模式。
- 最近检测时间、检测所用配置版本、各项能力及错误原因。

使用本阶段增量 Flyway 迁移，不改已执行脚本。协议由字段明确决定，不依端口猜测。表单按协议校验必填项和适用项，错误应定位到字段。

页面支持列表、新增、编辑、启用/停用和检测。列表展示协议、地址、启用状态、最近检测及时间；没有检测记录时显示“未检测”。先用停用代替硬删除，保留历史可引用性。

秘密字段留空表示保留原值；清除秘密必须是明确操作。敏感数据用外置主密钥加密或受限引用，修改凭据保存版本，不把旧秘密写进明文历史快照。SFTP 私钥只能引用管理员允许的受限目录。页面、响应和日志不回显原始密码、私钥或令牌。

## 二、实现一套可供业务层复用的文件客户端

在现有结构中建立小型协议接口及工厂，已有同职责组件就扩展。覆盖连接、列举、文件属性、读取、写入、建目录、改名、受控临时对象删除、能力查询和关闭。

FTP 适配使用原方案的 Apache Commons Net，SFTP 使用 Apache MINA SSHD；已有已验证依赖就沿用，否则固定可解析版本并记录。业务服务只依赖统一接口，不直接散落 FTP/SFTP 客户端调用。

FTP 使用二进制传输，实际验证数据通道；流式读写完成后检查最终命令响应。SFTP 必须验证已配置可信主机身份，再完成认证与文件操作，不使用无条件接受所有密钥的实现。每次操作/后续任务独占必要会话，异常与超时路径都关闭流和连接。

协议无远端哈希、容量或可靠路径辨识能力时，返回明确的未知/不支持结果，不把它转换成成功，也不默认借用远端 shell。

## 三、把“检测”实现为真实、受控、有结果的操作

检测由有超时、有界并发的执行器执行，HTTP 请求不无限等待。记录检测标识或状态，页面可以查询本次结果。处理顺序：

1. 校验当前配置、目录范围和 SFTP 可信身份；记录配置版本。
2. 连接并认证，区分连接、认证、主机身份失败。
3. 在授权范围内测试列举和读取；只读账户不尝试向业务目录写文件。
4. 配置了写探测范围时，在本次独占探测子目录写非空随机内容。
5. 取得实际大小与可用远端摘要，或完整回读刚写入的文件比较内容。
6. 在同一探测范围改名并确认结果。
7. 清理本次创建且归属明确的对象；清理失败记录残留位置和原因，不删除其他文件。
8. 保存各项结果、耗时和错误。容量查不到记 UNKNOWN，不填“空间充足”。

能力判定必须分别表达：只读但可下载的连接可用于拉取；无法远端哈希且无法回读的只写连接不满足严格推送。登录成功只代表连接/认证成功，不能直接标记全部能力通过。

编辑配置后，旧检测仍可追溯，但标记为旧版本结果；检测过程中被编辑的配置也不能把旧结果覆盖为新版本已通过。停用仅改变平台配置，不声称关闭远端 FTP/SFTP 服务。

## 四、提供真实测试和复现步骤

使用隔离 FTP、SFTP 测试服务与临时目录，完成真实连接、上传、读取、改名、清理测试；数据库持久化和配置版本用 PostgreSQL 验证。可复用已有嵌入式服务或容器夹具，不连接客户地址。

为只读、只写、错误主机密钥、数据通道故障、断网和清理失败准备可复现场景。检查句柄是否释放、探测是否超时结束、失败后有无越界删除。
