### 修复与回归

- 通知：ACK 使用 `ofInputStream`，从发送开始计 10 秒总期限，异步读取最多 4097 字节；超时或超限取消 future、关闭响应流，失败进入原有退避。真实 HTTP 测试覆盖 200 头后挂起、持续慢速体、无可信长度的超大体、后续正常通知，以及接收后主动断线丢 ACK。补发保持同编号与报文字节；接收端按 notificationId 只产生一次处理效果。
- 执行：`active.putIfAbsent` 在数据库领取前预留任务 ID，覆盖处理器和结果提交，异常与线程池拒绝均释放；过期但本进程仍活跃的任务跳过并继续扫描其他待执行任务。测试覆盖不并行、旧 claim 防迟到写回、真正孤儿恢复、池满保留、异常后恢复。
- 持久化：新增任务、产品、通知 JPA 实体及 Spring Data 仓储；`TransferJpa` 仓储内执行 PostgreSQL `ON CONFLICT`、条件领取与栅栏更新，服务层无 `JdbcTemplate` 或直接 SQL。保留三处短事务：任务+产品、结果+通知、ACK+预检后恢复排队。真实 PostgreSQL 的触发器故障注入分别验证三处回滚，并读取先前 V3 形态的记录。**生产 V3 迁移未修改，也无需新增迁移**；空 schema 初始化及现有升级测试通过。
- 入口：认证先于请求体读取，Servlet 流最多读取 32769 字节；超限返回 413 `REQUEST_TOO_LARGE`。真实 HTTP 验证正常请求、Content-Length、chunked、无令牌大请求；XML 保留 XXE 防护并限制 16 层、4096 节点。旧 XML 产品 ID 恰好 32 字符，JSON 仍为 1—100 字符，暂定 XML 默认关闭。
- 03-T02：方向、endpoint、产品、目标路径四种同号冲突均为 HTTP 409，原内容、状态、执行次数不变；03-T05 池满与过期任务防饥饿；03-T06 endpoint 编辑及 XML 路由修改后重放；03-T07 真实 ACK 丢失与接收端去重；03-T09 HTTP 字节限额、XML 结构及 XXE 拒绝。
