### 修改

P1：FtpRemoteFileClient 在连接前通过 socket factory 跟踪控制和被动数据 socket，主动模式同时跟踪监听和 accept 后的数据 socket。注册和关闭使用短锁，关闭后的迟到注册立即关闭资源；关闭幂等。先在锁内标记关闭并截取资源，再在锁外逐个关闭底层 socket，继续处理其他资源并保留关闭异常，最后 disconnect。不在计时器线程刷新或关闭缓冲输出流。远端流仍由工作线程的 try-with-resources 关闭，调用方 source / target 保持调用方所有权。RETR / STOR / LIST / stat 回退列举共享保护；保留单次 I/O 超时、最终完成响应检查、残留记录和超时终态保护，线程池仍为 2。

P2：删除写入目标回读后的 canRead=true；canRead 仅来自配置读源检测，verified 表示目标回读内容验证。isStrictPush 不新增读源成功前提。页面明确区分读源检测与写入目标完整性，README 同步。无数据库迁移、依赖、接口变更。

### 针对性测试

FtpCancellationTest 新增 7 项：主动 / 被动持续 RETR、STOR、主动 / 被动持续 LIST、被动连接等待初始响应期间关闭、主动 accept 阻塞关闭。验证 close 在 1 秒内返回、实际 I/O 线程 2 秒内退出、对端停止、调用方流未关闭及幂等。

EndpointIT 新增 5 项：两条持续 RETR 占用全局两个名额，在 socket 空闲超时 1 秒、数据每 20ms 节拍持续发送的情况下超过 6 秒总时限，验证 TIMED_OUT、对端均停止、两个工作线程均归零，然后新正常探测受理并完成、流量停止；真实 FTP/SFTP 分别验证分离读取和写入目录，读源拒绝但回读成功时 canRead=false / verified=true / strictPush=true；两协议分别验证读取对象缺失 / 读取根目录未配置不能被目标回读改成成功。既有正常、只读、只写及其他测试保留。
